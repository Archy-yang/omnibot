# v1.6 飞书机器人接入测试计划

---

## 测试目标

验证 OmniBot 飞书机器人接入(长连接 WebSocket)的端到端功能:消息收发、Agent 同步路径
处理、跨入口能力打通(长期记忆 / LLM 配置)、agent_steps 落库与 Web 流式端点对齐、
enabled 开关行为正确。

## 真实飞书端到端 smoke(待人工执行)

### 准备

1. 飞书开放平台创建**自建应用**(企业内部应用,无需审核)
2. 开启**机器人能力**,配置**长连接**接收(无需公网 URL)
3. 添加事件订阅 `im.message.receive_v1`
4. 添加权限:`im:message`(接收单聊消息)、`im:message:send_as_bot`(发消息)
5. 把应用上架到企业内,加机器人到通讯录
6. `configs/config.yaml` 加 feishu 段:

```yaml
feishu:
  app_id: "cli_xxx"
  app_secret: "your_secret"
  enabled: true
```

7. 启动后端:`./start.sh dev`,日志见 `feishu: starting long connection`

### 验证步骤

| # | 操作 | 期望 | 落库验证 |
|---|------|------|---------|
| 1 | 飞书 IM 单聊发「你好」 | 不调工具,回复正常文本 | agent_steps 仅 1 条 llm_call |
| 2 | 发「现在几点了」 | Agent 调 get_current_time → 回真实时间 | 3-step 链: llm_call→tool_call→llm_call |
| 3 | 发「帮我算 (123+456)*7」 | Agent 调 calculator → 回 4053 | 3-step 链,tool=calculator, response=4053 |
| 4 | 发非 text 消息(图片/语音) | 机器人不响应(v1.6 仅文本) | DB 无新增 message |
| 5 | 群聊 @ 机器人 | 不响应(v1.6 仅单聊) | DB 无新增 message |
| 6 | 同一 message_id 重复推送 | 机器人不重复回复 | SaveUserMessage 触发 ErrDuplicateMessage |
| 7 | 飞书发「#记住 我偏好简洁」 | 落 memories 表 | Web 端「我的记忆」可见该条 |
| 8 | Web 端配自定义 LLM 配置 | 飞书端用同一 model | agent_steps.model 字段 = 自定义模型名 |
| 9 | 设 enabled=false 重启 | 服务正常启动,飞书不连 | 日志 `feishu: channel disabled` |
| 10 | enabled=true 但 app_id 空 | 警告日志,服务不挂 | 日志 `feishu enabled but credentials missing` |

### 落库 SQL 速查

```sql
-- 查飞书用户的 user_channels
SELECT * FROM user_channels WHERE channel_type='feishu';

-- 查某轮对话的完整 agent_steps 链
SELECT seq, kind, tool, status, duration_ms, model,
       left(request, 40) AS req, left(response, 60) AS resp
FROM agent_steps WHERE message_id=? ORDER BY seq;

-- 验证 Web/飞书共享 user_id
SELECT u.id, COUNT(DISTINCT uc.channel_type) AS channels
FROM users u JOIN user_channels uc ON uc.user_id=u.id
GROUP BY u.id HAVING channels > 1;
```

### 关键验证点(架构核心)

- **Run/RunStream 记录一致**:同一用户先 Web 端流式问、再飞书端问,两条 message 的
  `agent_steps` 链路结构完全同款(都是 llm_call → 可选 tool_call → llm_call)。
- **跨入口共享 user_id**:同一用户在 Web 和飞书侧的 messages 表 user_id 相同。
