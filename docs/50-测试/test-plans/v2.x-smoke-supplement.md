## 分层执行原则

smoke 分两层,不同执行主体:

| 层 | 执行者 | 覆盖 | 依赖 |
|----|--------|------|------|
| **A. API 层冒烟** | AI 全自动 | 路由通/DB 落库/JWT 鉴权/绑定码全流程/错误码映射 | 仅后端 + DB,不需要真实 LLM/飞书/微信 |
| **B. 真实端到端** | 用户手测 | 浏览器登录注册/真实 LLM 对话/飞书微信端发消息 | 真实凭证 + 浏览器 + 飞书/微信 App |

AI 把 A 跑完并记录证据,B 列清单交给用户。

### A.1 v2.1 邮箱登录(无鉴权端点)

| 用例 | 请求 | 预期 |
|------|------|------|
| 注册成功 | `POST /api/v1/auth/register` {email, password, confirm_password} | 200 + `{token}`;DB users + user_channels(email) + user_credentials 各落 1 行 |
| 重复邮箱 | 同邮箱再注册 | 409 + `该邮箱已注册,请直接登录` |
| 密码太短 | password=7 位 | 400 + `密码长度需为 8~64 位` |
| 邮箱格式错 | email=noatsign | 400 + `请输入有效的邮箱地址` |
| 两次密码不一致 | password ≠ confirm | 400 + `两次输入的密码不一致` |
| 登录成功 | `POST /api/v1/auth/login` | 200 + `{token}` |
| 登录密码错 | wrong password | 401 + `邮箱或密码错误` |
| 登录未注册 | 新邮箱 | 401 + `邮箱或密码错误`(防枚举:与密码错同文案) |
| 大小写归一 | 用大写邮箱注册,小写登录 | 200(归一化生效) |
| 受保护端点无 token | `GET /api/v1/chat/messages` | 401 + `unauthorized` |
| 受保护端点带 token | 带 Bearer | 200(鉴权通过) |

### A.2 v2.2/v2.3 渠道绑定(鉴权端点)

注册账号 A + 账号 B,用 A 的 token:

| 用例 | 请求 | 预期 |
|------|------|------|
| 查状态(全未绑) | `GET /api/v1/user/channel-binding` | 200 + `{feishu_bound:false, wechat_bound:false}` |
| 出码 | `POST /api/v1/user/channel-binding/bind-code` | 200 + `{code:6位, expires_at, expires_in}`;DB bind_codes 落 1 行 |
| 重新出码作废旧码 | 再 POST 一次 | 新码不同;DB 仍 1 行(upsert 覆盖) |
| 飞书绑定成功 | (模拟)直接调 BindingService.BindChannel("feishu", code, "ou_test") | nil;user_channels 落 feishu 行 |
| 查状态(飞书已绑) | GET | `{feishu_bound:true, wechat_bound:false}` |
| 仍可出码绑微信 | POST bind-code | 200(未全绑,可出码) |
| 飞书号已占 | BindChannel("feishu", B的码, "ou_test") | ErrChannelAlreadyBound |
| 账号已绑该渠道 | A 再出码绑另一个飞书号 | ErrAccountAlreadyBound |
| 全绑后出码 | 飞书+微信都绑后 POST | 409 + `你的账号已绑定全部渠道` |

> 注:BindChannel 是 service 方法,API 层无直接端点(由飞书/微信 channel 调)。
> A.2 用 SQL 直接验证 user_channels 落库 + 手工调 service 验证绑定逻辑。

### A.3 跨入口身份统一(核心验证)

注册账号 A,绑飞书 ou_f + 微信 wx_w。验证:
- `SELECT user_id FROM user_channels WHERE channel_type='feishu' AND channel_user_id='ou_f'` = A.id
- `SELECT user_id FROM user_channels WHERE channel_type='wechat' AND channel_user_id='wx_w'` = A.id
- 两个 user_id 相同 = 三入口同一身份

## B. 真实端到端(用户手测)

### B.1 v2.1 浏览器登录注册

- 访问 -> 重定向 `/login`
- 注册 -> 自动登录进主页
- 发消息 -> 刷新历史还在
- 设置抽屉登出 -> 回登录页
- 重新登录

### B.2 v2.2/v2.3 渠道绑定 UI

- 设置抽屉「渠道绑定」区块:飞书/微信两行状态
- 点「获取绑定码」-> 6 位码 + 倒计时 + 操作说明
- 倒计时归零码置灰

### B.3 飞书端真实绑定 + 对话(需飞书自建应用)

- 飞书向机器人发 `绑定 <码>` -> 回复「绑定成功!现在可以在飞书跟我聊了」
- 飞书发普通消息 -> 用 web 账号身份对话,能看到 web 端历史/记忆
- 未绑飞书号发消息 -> 回引导(不建号)
- 码过期后绑 -> 「绑定码无效或已过期」

### B.4 微信端真实绑定(需测试号 + ngrok)

- 微信发 `绑定 <码>` -> 「绑定成功!现在可以在微信跟我聊了」
- 微信发普通消息 -> web 账号身份对话
- 未绑微信号发消息 -> 回引导
- 新号关注公众号 -> 欢迎语+引导(不建号)
- 未绑发 `#模型设置` -> 回引导(不执行命令)

### B.5 真实 LLM 对话(v1.5 Agent,沿用 v1.11 Phase 2.3)

- 设置面板配真实 LLM(DeepSeek/豆包)
- `现在几点了` -> 调 get_current_time 工具
- `帮我算 (123+456)*7` -> 调 calculator,答案 4053
- 验证 agent_steps 落库

### B.6 跨渠道数据互通(核心)

同账号绑飞书+微信后:
- web 说「我叫张三」-> 飞书问「我叫什么」-> 知道张三
- 微信加一条记忆 -> web 记忆列表可见

## 问题分级

- **P0**:阻塞核心流程(登录失败/绑定失败/鉴权失效/数据串号),必须立即修
- **P1**:功能可用但有缺陷(错误文案不对/状态不刷新/边界没处理),本期修
- **P2**:体验问题/小 bug,记录,后续修

所有发现写入 `docs/50-测试/test-reports/v2.x-smoke-report.md`。
