# v1.5 Agent 基本能力测试计划

---

## 测试目标

验证 OmniBot Web 端支持 Agent 基本能力：Tool Registry、OpenAI Function Calling 协议、ReAct 多步循环、内置工具调用，以及 Agent 执行过程通过 SSE 事件推送给前端。

---

## 测试范围

| 范围 | 覆盖 |
|------|------|
| Tool Registry | 工具注册、重名校验、查询、列表、OpenAI tools 格式转换 |
| Built-in Tools | `get_current_time`、`calculator`、`search_memories`、`search_history` |
| ReAct Agent | 无工具调用、单工具调用、工具失败、最大步数终止 |
| Web API | Agent 同步端点和 SSE 端点注册与调用 |
| Frontend | Agent SSE 事件解析、思考过程展示、构建通过 |

## 后端测试用例

### Tool Registry

- 注册新工具成功
- 重复注册同名工具返回错误
- 查询已注册工具成功
- 查询不存在工具返回 false
- `ToOpenAITools()` 输出符合 OpenAI Function Calling 的 `tools` 格式

### Built-in Tools

| 工具 | 用例 | 期望 |
|------|------|------|
| `get_current_time` | 无参数调用 | 返回非空当前时间字符串 |
| `calculator` | `2 + 3` | 返回 `5` |
| `calculator` | `(2+3)*4` | 返回 `20` |
| `calculator` | 非法字符 | 返回错误 |
| `search_memories` | 匹配关键词 | 返回匹配记忆 |
| `search_memories` | 无匹配 | 返回未找到提示 |
| `search_history` | v1.5 placeholder | 返回后续版本提示 |

### ReAct Agent

- 普通消息：LLM 无 `tool_calls`，直接返回最终文本
- 单工具调用：LLM 调用工具，Agent 执行工具并把结果回传，再返回最终文本
- 工具失败：工具错误作为 observation 回传，Agent 不崩溃
- 最大步数：达到限制后返回包含「已达到最大步数」的提示

落库验证：
- **v1.5.4 segments**：tool 段带工具名/文案/脱敏 result，JSON 结构往返一致（msg 71/73/77）
- **v1.5.5 agent_steps**：`message_id + seq` 还原完整有序链，tool 步骤 response 存**原始未脱敏**
  结果（含真实错误），llm_call 步骤存 request messages 快照 + response `{content,tool_calls}`

### Smoke 观察到的非阻塞问题（记录待后续评估，不属 v1.5 缺陷）

1. **上下文偷懒**：同一 user 的滑动窗口历史会让模型引用旧答案而不重新调工具
   （如再问「现在几点」时复用历史时间 msg 69、再问 rss 失败时文本伪造 msg 76）。
   这是 ReAct + 滑动窗口的预期行为，但影响 smoke 可复现性，也是连续提问场景的体验隐患。
2. **search_memories 召回局限**：工具为关键词匹配，记忆内容是纯数字「23456」时，
   模型用语义词（记忆/所有/信息）搜不到，进而给出「没有存储任何内容」的错误结论（msg 73）。
3. **脱敏边界**：`sanitizeToolResult` 覆盖 SSE tool_result 事件与 segments，但工具原始错误
   会进下一轮 LLM 上下文（PRD 5.5 错误回传设计），模型可能在最终文本里复述原始错误细节
   （msg 77 seq2），绕过展示层脱敏。错误本身不含 IP/堆栈等高危信息，但超出「工具执行失败」
   的脱敏意图——是否收紧取决于安全红线严格度。
