## 二、需求背景与目标

### 2.1 背景

长期记忆 MVP 已支持微信公众号入口，用户可以通过 `#记住`、`#我的记忆`、`#清空记忆` 管理长期记忆，并在普通对话中自动使用最近 10 条长期记忆。

Web 端当前已有普通聊天入口，并且后端消息上下文构建复用统一的消息上下文能力，因此 Web 普通对话具备自动使用长期记忆的基础。但 Web 端还没有可视化的长期记忆管理能力，用户无法在 Web 页面查看、添加或清空自己的长期记忆。

### 2.2 问题

1. Web 用户无法直观看到助手当前长期记住了什么。
2. Web 用户无法通过页面主动添加长期记忆。
3. Web 用户无法通过页面清空错误或过期的长期记忆。
4. 如果 Web 端长期记忆只能依赖命令输入，体验不符合 Web 产品习惯。

### 2.3 目标

> 在 Web 端提供简单、可控、可视化的长期记忆管理能力，让用户可以查看、新增、清空长期记忆，并在普通聊天中自然使用这些记忆。

## 三、产品范围

### 3.1 本次 MVP 做什么

1. Web 端提供长期记忆管理入口。
2. 用户可以查看当前已保存的全部长期记忆。
3. 用户可以新增一条长期记忆。
4. 用户可以一键清空全部长期记忆。
5. 用户新增记忆时看到敏感信息提醒。
6. Web 普通聊天继续自动使用最近 10 条长期记忆。
7. Web 端长期记忆能力复用统一用户维度，不引入独立的 Web-only 记忆。

### 3.2 本次 MVP 不做什么

1. 不做自动记忆提取。
2. 不做向量相似度召回。
3. 不做记忆分类、重要性评分、置顶。
4. 不做单条删除。
5. 不做单条编辑。
6. 不做批量选择。
7. 不做搜索。
8. 不做分页。
9. 不做导入导出。
10. 不做复杂隐私设置。
11. 不新增独立的复杂记忆中心页面。

### 3.3 与现有长期记忆 MVP 的关系

Web 端长期记忆管理不重新定义记忆模型，只是为已有长期记忆能力补充 Web 管理入口。

- 微信公众号入口：通过命令管理长期记忆。
- Web 入口：通过可视化界面管理长期记忆。
- 普通对话：两个入口都应使用同一用户维度下的长期记忆能力。

## 五、Web 交互流程

### 5.1 管理入口

Web 端在现有聊天体验中增加长期记忆管理入口。

MVP 推荐形态：

- 放在现有设置面板或侧边设置区域中。
- 入口名称：`长期记忆`。
- 不新增独立路由页面，避免 MVP 范围扩大。

用户打开长期记忆管理区域后，可以看到：

1. 当前长期记忆列表。
2. 新增长期记忆输入框。
3. 保存按钮。
4. 清空全部长期记忆按钮。
5. 敏感信息提醒。

### 5.2 查看记忆

用户打开长期记忆管理区域时，系统加载当前用户的全部长期记忆。

有记忆时展示：

```text
我目前记住了这些信息：

1. 我偏好简洁直接的回答
2. 我正在开发 OmniBot 项目
3. 我主要使用 Go 语言
```

没有记忆时展示：

```text
我还没有长期记住任何信息。

你可以添加一条希望助手长期记住的偏好、背景或项目说明。
```

### 5.3 新增记忆

用户输入一条长期记忆后点击保存。

输入示例：

```text
我偏好简洁直接的回答
```

成功后提示：

```text
已记住。

提醒：请不要保存密码、API Key、身份证号等敏感信息。
```

保存成功后：

1. 清空输入框。
2. 刷新长期记忆列表。
3. 新增的记忆出现在列表中。

如果内容为空，提示：

```text
请输入要长期记住的内容。
```

如果内容过长，提示：

```text
这条记忆太长了，请控制在 200 字以内。
```

如果服务异常，提示：

```text
服务暂时不可用，请稍后再试。
```

### 5.4 清空记忆

用户点击 `清空全部长期记忆` 时，需要二次确认。

确认文案：

```text
确定要清空全部长期记忆吗？清空后无法恢复。
```

用户确认后，系统清空当前用户的全部长期记忆。

成功提示：

```text
已清空你的全部长期记忆。
```

清空成功后：

1. 记忆列表变为空状态。
2. 不影响短期聊天历史。
3. 不影响用户自定义 LLM 配置。

如果服务异常，提示：

```text
服务暂时不可用，请稍后再试。
```

### 5.5 普通聊天使用长期记忆

Web 普通聊天不需要新增用户操作。

```text
用户发送普通消息
  ↓
系统识别当前 Web 用户
  ↓
获取用户最近 10 条长期记忆
  ↓
与最近短期上下文一起构建 LLM messages
  ↓
LLM 生成回复
  ↓
保存本轮短期对话消息
  ↓
返回用户
```

记忆注入对用户无感知，界面不额外显示「已参考长期记忆」。

## 六、数据规则

### 6.1 长期记忆内容

- 每条记忆属于一个用户。
- 每条记忆是一段用户显式输入的文本。
- 单条记忆最大长度：200 个 Unicode 字符。
- 记忆按创建时间排序。
- 管理列表 MVP 阶段展示全部长期记忆。
- 普通聊天最多注入最近 10 条长期记忆。
- 允许用户保存重复内容。

### 6.2 用户隔离

- Web 端通过当前 `session_id` 映射到用户。
- 不同 Web 用户不能看到彼此的长期记忆。
- 清空长期记忆只影响当前用户。
- 后续如果同一用户绑定多个入口，应以统一 `UserID` 共享长期记忆。

### 6.3 隐私与安全

- 用户保存记忆时，需要展示安全提醒。
- 日志不记录完整记忆内容。
- 日志不记录完整用户对话内容。
- 对外错误不暴露数据库、SQL、堆栈等内部实现细节。
- MVP 不做敏感信息强识别，不阻止用户保存普通文本。

## 七、接口需求

Web 端需要具备以下记忆管理能力，具体接口路径和字段可在技术设计阶段最终确认。

### 7.1 获取记忆列表

用途：获取当前 Web 用户的全部长期记忆。

请求参数：

- `session_id`：当前 Web 会话标识。

成功响应应包含：

- 记忆 ID。
- 记忆内容。
- 创建时间。

空列表时返回空数组，不返回错误。

### 7.2 新增记忆

用途：为当前 Web 用户新增一条长期记忆。

请求字段：

- `session_id`：当前 Web 会话标识。
- `content`：要保存的长期记忆内容。

成功响应应包含：

- 成功提示文案。
- 新创建的记忆信息。

### 7.3 清空记忆

用途：清空当前 Web 用户的全部长期记忆。

请求参数：

- `session_id`：当前 Web 会话标识。

成功响应应包含：

- 成功提示文案。

## 八、异常与边界处理

| 场景 | 处理 |
|------|------|
| 缺少 `session_id` | 返回参数错误提示 |
| 新增记忆内容为空 | 返回 `请输入要长期记住的内容。` |
| 新增记忆超过 200 字 | 返回 `这条记忆太长了，请控制在 200 字以内。` |
| 获取记忆列表失败 | 返回 `服务暂时不可用，请稍后再试。` |
| 新增记忆失败 | 返回 `服务暂时不可用，请稍后再试。` |
| 清空记忆失败 | 返回 `服务暂时不可用，请稍后再试。` |
| 无记忆时查看列表 | 展示空状态和引导文案 |
| 无记忆时清空 | 返回 `已清空你的全部长期记忆。` |
| 普通聊天记忆查询失败 | 降级为无长期记忆对话，不影响回复 |

## 九、非功能需求

| 项目 | 要求 |
|------|------|
| 性能 | 记忆列表加载不应明显影响 Web 设置面板打开体验。 |
| 可靠性 | 普通聊天中的长期记忆查询失败时，必须降级为无长期记忆对话。 |
| 安全 | 日志不输出完整记忆内容或完整用户对话内容。 |
| 可控性 | 用户必须能查看和清空 Web 端可用的长期记忆。 |
| 兼容性 | 不影响现有 Web 聊天、微信公众号记忆命令、用户自定义 LLM 配置。 |
| 可演进性 | Web 端能力应复用统一长期记忆服务，后续支持单条删除、编辑、分类时不重复建设。 |

## 十、埋点与观测指标

MVP 不要求先建设完整埋点系统，但上线后需要能观察这些指标。

| 指标 | 用途 |
|------|------|
| web_memory_list_count | 观察 Web 用户是否查看长期记忆。 |
| web_memory_created_count | 观察 Web 用户是否主动保存长期记忆。 |
| web_memory_clear_count | 观察 Web 用户清空长期记忆的频率。 |
| web_memory_create_failed_count | 观察 Web 新增长期记忆失败情况。 |
| web_memory_query_failed_count | 观察 Web 记忆查询稳定性。 |

日志和指标只记录操作类型、用户 ID、数量、耗时、错误类型，不记录完整记忆内容。

## 十三、对当前项目的影响

### 13.1 需要新增或调整的能力

1. Web 端提供长期记忆管理入口。
2. Web 后端提供长期记忆管理能力给前端使用。
3. 前端需要展示长期记忆列表、新增输入、清空操作和安全提醒。
4. 普通 Web 聊天需要保持长期记忆自动注入能力。

### 13.2 不应影响的能力

- 当前 Web 普通聊天。
- 当前微信公众号长期记忆命令。
- 当前短期上下文记忆。
- 当前用户自定义 LLM 配置。
- 当前消息落库与历史记录能力。

## 十四、风险与应对

| 风险 | 影响 | 应对 |
|------|------|------|
| 用户误存敏感信息 | 中 | 在新增记忆区域和保存成功提示中提醒不要保存密码、API Key、身份证号等敏感信息。 |
| 用户清空后反悔 | 中 | 清空前二次确认，并明确提示清空后无法恢复。 |
| 记忆过多导致列表变长 | 低 | MVP 展示全部记忆，后续再增加分页或搜索。 |
| Web 与微信记忆表现不一致 | 中 | 复用同一长期记忆能力和相同数据规则。 |
| 长期记忆查询失败影响聊天 | 高 | 普通聊天中查询失败必须降级为无长期记忆对话，不中断回复。 |
