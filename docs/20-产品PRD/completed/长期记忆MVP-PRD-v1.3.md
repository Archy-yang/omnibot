## 二、需求背景与目标

### 2.1 背景

当前系统已经支持「最近 10 轮对话上下文记忆」，可以让用户在短时间内进行连续多轮对话。但这种记忆只解决短期上下文问题，无法让助手长期记住用户的偏好、习惯、身份信息和持续项目背景。

产品愿景 v2.0 明确要求 OmniBot 成为「自带记忆的全平台智能助手」，核心差异化是：不管用户从哪个入口对话，助手都能长期记住用户的重要信息，减少重复解释，形成越来越懂用户的体验。

### 2.2 问题

1. 用户每次开始新话题时，仍需要重复说明自己的偏好、项目背景和使用习惯。
2. 当前短期上下文窗口会随着对话推进被截断，无法承载长期稳定信息。
3. 如果没有用户可控的长期记忆能力，后续自动记忆提取、向量召回、跨入口统一记忆都缺少产品基础。

### 2.3 目标

> 让用户可以通过显式命令告诉助手「请长期记住这件事」，助手在后续普通对话中自动使用这些记忆，形成「越来越懂我」的基础体验。

## 三、产品范围

### 3.1 本次 MVP 做什么

1. 用户发送 `#记住 xxx`，系统保存一条长期记忆。
2. 用户发送 `#我的记忆`，系统返回当前已保存的记忆列表。
3. 用户发送 `#清空记忆`，系统清空该用户的全部长期记忆。
4. 用户后续普通对话时，系统自动把最近 10 条长期记忆注入 LLM 上下文。
5. 记忆能力设计为入口无关核心能力，但本次产品验收只覆盖微信公众号入口。

### 3.2 本次 MVP 不做什么

1. 不做自动记忆提取。
2. 不做向量相似度召回。
3. 不做记忆分类、重要性评分。
4. 不做单条编辑。
5. 不做敏感信息强识别，只做安全提示、长度限制和日志脱敏。

### 3.3 与现有记忆能力的关系

长期记忆不替代当前「最近 10 轮上下文记忆」。

- 短期上下文记忆：用于理解当前连续对话中的指代、上下文和最近讨论内容。
- 长期画像记忆：用于保存用户长期稳定的信息，例如偏好、习惯、身份、长期项目背景。

普通对话时，两类记忆可以同时参与 LLM 上下文构建。

## 五、微信交互流程

### 5.1 新增记忆

用户输入：

```text
#记住 我偏好简洁直接的回答
```

成功返回：

```text
已记住：我偏好简洁直接的回答

提醒：请不要保存密码、API Key、身份证号等敏感信息。
```

如果内容为空：

```text
请在 #记住 后面输入要长期记住的内容，例如：
#记住 我偏好简洁直接的回答
```

如果内容过长：

```text
这条记忆太长了，请控制在 200 字以内。
```

### 5.2 查看记忆

用户输入：

```text
#我的记忆
```

有记忆时返回：

```text
我目前记住了这些信息：

1. 我偏好简洁直接的回答
2. 我正在开发 OmniBot 项目
3. 我主要使用 Go 语言
```

没有记忆时返回：

```text
我还没有长期记住任何信息。

你可以这样告诉我：
#记住 我偏好简洁直接的回答
```

### 5.3 清空记忆

用户输入：

```text
#清空记忆
```

返回：

```text
已清空你的全部长期记忆。
```

### 5.4 删除单条记忆

用户输入：

```text
#删除记忆 2
```

成功返回：

```text
已删除记忆：我正在开发 OmniBot 项目
```

序号超出范围时返回：

```text
记忆序号不存在，请发送 #我的记忆 查看当前列表。
```

格式错误时返回：

```text
请发送 #删除记忆 序号，例如：#删除记忆 2
```

### 5.5 Web 记忆管理

Web 端通过 API 提供记忆管理能力：

- `GET /api/v1/memories` - 获取记忆列表
- `POST /api/v1/memories` - 新增记忆
- `DELETE /api/v1/memories` - 清空全部记忆
- `DELETE /api/v1/memories/:id` - 删除单条记忆
- `PUT /api/v1/memories/:id` - 更新单条记忆

### 5.6 普通对话使用流程

```text
用户发送普通消息
  ↓
识别不是记忆命令
  ↓
获取用户最近 10 条长期记忆
  ↓
与最近 10 轮短期上下文一起构建 LLM messages
  ↓
LLM 生成回复
  ↓
保存本轮短期对话消息
  ↓
返回用户
```

记忆注入对用户无感知，不额外回复「我参考了你的记忆」。

## 六、数据规则

### 6.1 长期记忆内容

- 每条记忆属于一个用户。
- 每条记忆是一段用户显式输入的文本。
- 单条记忆最大长度：200 个中文字符或等价长度文本。
- 记忆按创建时间排序。
- 普通对话时最多注入最近 10 条长期记忆。
- `#我的记忆` MVP 阶段返回全部记忆；如果后续数量过多，再增加分页或只返回最近 N 条。

### 6.2 记忆隔离

- 不同用户的长期记忆完全隔离。
- 微信入口以当前已绑定/创建的 UserID 作为记忆归属。
- 未来 Web/API 入口复用同一 UserID 维度的记忆能力。

### 6.3 隐私与安全

- 用户保存记忆时，返回安全提示：不要保存密码、API Key、身份证号等敏感信息。
- 日志不记录完整记忆内容，只允许记录 user_id、memory_id、内容长度、操作类型。
- MVP 不做敏感内容强识别，不阻止用户保存普通文本。
- 清空记忆只影响该用户自己的长期记忆，不影响短期对话历史。

## 七、异常与边界处理

| 场景 | 处理 |
|------|------|
| `#记住` 后没有内容 | 返回示例提示，不保存 |
| `#记住` 内容超过 200 字 | 返回长度限制提示，不保存 |
| `#我的记忆` 时没有记忆 | 返回空状态提示和示例 |
| `#清空记忆` 时没有记忆 | 返回「已清空你的全部长期记忆」 |
| 保存记忆失败 | 返回「服务暂时不可用，请稍后再试」，内部记录错误日志 |
| 查询记忆失败 | 普通对话降级为不注入长期记忆，但不影响回复 |
| 清空记忆失败 | 返回「服务暂时不可用，请稍后再试」，内部记录错误日志 |
| 删除记忆序号不存在 | 返回「记忆序号不存在，请发送 #我的记忆 查看当前列表。」 |
| 删除记忆失败 | 返回「服务暂时不可用，请稍后再试」，内部记录错误日志 |
| 普通对话中记忆数量超过 10 条 | 只注入最近 10 条 |
| 用户输入类似 ` #记住 xxx` | 去除首尾空格后识别命令 |
| 用户输入 `#记住    xxx` | 折叠命令后的前导空白，保存 `xxx` |

## 八、非功能需求

| 项目 | 要求 |
|------|------|
| 性能 | 长期记忆查询和注入增加的耗时应小于 50ms，不明显影响普通对话响应。 |
| 可靠性 | 长期记忆查询失败时必须降级为无长期记忆对话，不能中断普通对话。 |
| 安全 | 不在日志中输出完整记忆内容；对外错误不暴露数据库、SQL、内部堆栈等实现细节。 |
| 可控性 | 用户必须能通过 `#我的记忆` 查看长期记忆，并通过 `#清空记忆` 清空全部长期记忆。 |
| 兼容性 | 不影响现有短期上下文记忆、微信消息处理、自定义 LLM 配置。 |
| 可演进性 | 领域能力必须入口无关，后续可被 Web/API/飞书等入口复用。 |

## 九、埋点与观测指标

MVP 不要求先建设完整埋点系统，但上线后需要能观察这些指标。

| 指标 | 用途 |
|------|------|
| memory_created_count | 观察用户是否愿意主动保存长期记忆。 |
| memory_list_count | 观察用户是否关心「助手记住了什么」。 |
| memory_clear_count | 观察记忆误存、过期或信任问题。 |
| memory_injected_count | 观察长期记忆实际参与回复的次数。 |
| memory_query_failed_count | 观察长期记忆模块稳定性。 |
| avg_memories_per_user | 观察长期记忆使用深度。 |

日志和指标只记录操作类型、用户 ID、数量、耗时、错误类型，不记录完整记忆内容。

## 十、验收标准

- [ ] 用户发送 `#记住 我偏好简洁回答` 后，系统返回「已记住」并保存该记忆。
- [ ] 用户发送 `#我的记忆` 后，可以看到刚才保存的记忆。
- [ ] 用户保存超过 10 条记忆后，普通对话只注入最近 10 条。
- [ ] 用户发送 `#清空记忆` 后，再发送 `#我的记忆` 显示没有长期记忆。
- [ ] 普通对话时，LLM 请求中包含长期记忆内容，用于影响回复。
- [ ] 记忆查询失败时，普通对话仍可继续，只是不注入长期记忆。
- [ ] 日志中不输出完整记忆内容。
- [ ] 不同用户之间不能看到或使用彼此的长期记忆。
- [ ] 当前短期上下文记忆功能不受影响。
- [ ] 用户自定义 LLM 配置功能不受影响。

## 十二、对当前项目的影响

### 12.1 需要新增或调整的能力

1. 新增长期记忆领域能力，按用户维度保存用户画像型记忆。
2. 新增长期记忆服务能力，提供新增、列表、清空、获取最近 N 条记忆的入口无关接口。
3. 微信消息处理增加长期记忆命令识别。
4. 普通对话构建 LLM 上下文时注入最近 10 条长期记忆。

### 12.2 不应影响的能力

- 当前短期上下文记忆。
- 微信签名验证和消息解析。
- 用户自定义 LLM 配置。
- 消息去重和消息永久落库。
- Web/API 后续入口扩展能力。

## 十三、风险与应对

| 风险 | 影响 | 应对 |
|------|------|------|
| 用户误存敏感信息 | 中 | 保存成功提示中明确提醒不要保存密码、API Key、身份证号等敏感信息；日志不输出完整内容。 |
| 记忆过多导致上下文干扰 | 中 | 普通对话只注入最近 10 条，后续再做分类和相关性召回。 |
| 错误记忆无法单条删除 | 中 | MVP 提供清空全部能力；单条删除进入后续增强。 |
| 长期记忆查询失败影响对话 | 高 | 查询失败时降级为无长期记忆对话，不中断普通回复。 |
| 用户不知道可以使用长期记忆 | 低 | 后续可在欢迎语或帮助命令中补充提示，本 MVP 先聚焦核心闭环。 |
