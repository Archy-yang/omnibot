# PRD：大模型客户端接入

## 需求背景

当前系统已经完成微信公众号接入，能够接收用户消息并返回固定占位回复。下一步需要接入大语言模型，实现真正的智能对话回复。

为了适配国内微信服务，优先接入国内大模型厂商：**阿里通义千问** + **字节豆包**。

为了保证系统灵活性，需要支持多个大模型厂商，可配置切换，并支持故障自动降级。

## 业务目标

1. 用户发送消息 → 系统调用大语言模型 → 返回智能回复给用户
2. 支持同时配置多个厂商（通义千问、豆包）
3. 可通过配置指定默认使用哪个厂商
4. 默认厂商不可用时，自动按顺序降级到备用厂商
5. 未来方便添加新的大模型厂商

## 用户故事

| 角色 | 动作 | 期望 |
|------|------|------|
| 终端用户 | 在微信公众号发送文字消息 | 获得大模型生成的智能回复 |
| 系统管理员 | 在配置文件中修改厂商优先级 | 系统按配置的优先级使用大模型 |
| 系统管理员 | 默认厂商 API 服务故障 | 系统自动降级使用下一个备用厂商继续服务 |
| 系统管理员 | 想要切换默认厂商 | 修改配置即可，不需要修改代码 |
| 开发者 | 需要添加新的大模型厂商 | 只需要新增一个实现，不影响现有代码 |

## 功能需求

### 1. 多厂商配置管理

- 系统支持同时配置多个大模型厂商
- 每个厂商需要单独配置认证信息和参数
- 指定默认厂商和降级顺序

### 2. 统一对话接口

- 上层对话服务不关心具体使用哪个厂商
- 通过统一接口调用对话请求
- 返回统一格式的回复结果

### 3. 通义千问支持

- 对接阿里通义千问官方 API
- 正确发送对话历史
- 正确接收模型回复

### 4. 字节豆包支持

- 对接字节豆包官方 API
- 正确发送对话历史
- 正确接收模型回复

### 5. 工厂创建

- 根据配置自动创建所有厂商的客户端实例
- 提供获取默认客户端的方法
- 支持按降级顺序获取下一个可用客户端

### 6. 自动降级

- 默认厂商调用失败（网络错误、API 错误、超时）
- 自动按配置的降级顺序尝试下一个厂商
- 所有厂商都失败才返回最终错误
- 记录每个厂商调用失败日志

## 非功能需求

- 请求支持超时控制，每个厂商独立配置超时时间
- 记录详细日志，便于排查问题
- 接口抽象方便单元测试
- 新增厂商不影响现有代码结构
