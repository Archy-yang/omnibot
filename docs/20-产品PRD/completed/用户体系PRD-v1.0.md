## 2. 项目背景

### 2.1 问题描述

当前系统已完成微信公众号接入，可以接收并回复用户消息，但尚未建立自有用户体系：
- 无法识别和追踪独立用户
- 所有用户消息无差别处理，无法实现个性化服务
- 缺少用户维度的数据沉淀，无法支持后续业务扩展

### 2.2 业务目标

**一期目标**：
- 建立自有用户体系基础
- 微信公众号用户与自有用户自动关联
- 为后续个性化对话、记忆系统等功能提供用户维度支撑

**二期规划**（预留设计）：
- 支持手机号绑定/解绑
- 支持手机号独立登录
- 跨应用（多公众号/小程序/APP）用户统一

## 4. 功能需求

### 4.1 用户自动创建（一期）

#### 4.1.1 关注触发创建
- **触发时机**：用户首次关注公众号时，收到 `subscribe` 事件
- **处理逻辑**：
  1. 解析微信回调事件，获取用户 OpenID
  2. 查询用户表，检查该 OpenID 是否已存在
  3. 若不存在，创建新用户记录
  4. 若已存在，更新用户状态（如有必要）
- **输入**：微信 subscribe 事件（含 OpenID）
- **输出**：用户记录创建成功/失败

#### 4.1.2 消息触发兜底创建
- **触发时机**：用户发送任意类型消息时
- **处理逻辑**：
  1. 解析微信消息，获取用户 OpenID
  2. 查询用户表，检查该 OpenID 是否已存在
  3. 若不存在，创建新用户记录（兜底）
  4. 继续后续消息处理流程
- **输入**：微信任意消息（含 OpenID）
- **输出**：用户记录创建成功/失败（不影响消息处理）

### 4.2 用户数据范围

#### 4.2.1 一期存储范围
- 用户唯一标识（微信侧）
- 用户状态

#### 4.2.2 二期预留能力
- 手机号绑定相关数据

## 5. 非功能需求

### 5.1 性能要求
- 用户创建操作响应时间 < 100ms
- 支持并发创建用户（微信回调并发场景）
- 数据库唯一索引保证幂等性

### 5.2 可靠性要求
- 用户创建失败不影响消息正常处理
- 重复创建请求幂等处理（不会创建重复用户）

### 5.3 可扩展性要求
- 预留 UnionID 字段，支持后续跨应用用户统一
- 预留手机号相关字段，支持后续手机号绑定功能
- 用户状态字段支持后续扩展（如封禁、删除等）

## 6. 业务流程

### 6.1 用户创建流程

```
用户关注公众号 / 发送消息
        ↓
微信服务器回调
        ↓
签名验证通过
        ↓
解析 OpenID
        ↓
查询用户表是否存在该 OpenID
        ├─ 存在 → 继续后续流程
        └─ 不存在 → 创建新用户记录
                    ↓
                 继续后续流程
```

## 7. 二期功能规划（预留设计）

### 7.1 手机号绑定流程
1. 用户请求绑定手机号
2. 系统发送短信验证码
3. 用户输入验证码
4. 验证通过，绑定手机号到用户记录
5. 记录绑定时间和验证状态

### 7.2 手机号登录流程
1. 用户输入手机号
2. 系统发送短信验证码
3. 用户输入验证码
4. 验证通过，查询或创建用户
5. 颁发登录凭证（Token）

### 7.3 跨应用用户统一
- 基于 UnionID 实现同一微信开放平台下多应用用户统一
- 用户在不同应用（公众号A、公众号B、小程序、APP）的行为归属到同一用户

## 8. 验收标准

### 8.1 功能验收
- [ ] 用户首次关注公众号，系统自动创建用户记录
- [ ] 用户发送消息，若用户不存在，系统自动创建用户记录
- [ ] 重复关注/发送消息不会创建重复用户
- [ ] 用户表包含所有预留字段（phone、phone_verified、phone_bind_time）
- [ ] OpenID 和 UnionID 有唯一索引约束

### 8.2 非功能验收
- [ ] 用户创建操作响应时间 < 100ms
- [ ] 并发场景下无重复用户创建
- [ ] 用户创建失败不影响消息回复
