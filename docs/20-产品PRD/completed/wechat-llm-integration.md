# PRD：微信处理器集成大模型生成回复

## 需求背景

大模型客户端已经开发完成，现在需要在微信消息处理器中集成大模型，将原来的固定占位回复改为调用大模型生成真正的智能回复。

## 业务目标

用户发送消息 → 微信服务器 → 我们服务 → 调用大模型 → 获取生成回复 → 返回给用户

## 用户故事

| 角色 | 动作 | 期望 |
|------|------|------|
| 终端用户 | 在微信公众号发送文字消息 | 获取大模型生成的智能回复 |
| 系统管理员 | 配置了大模型 API Key | 系统能够正常调用大模型生成回复 |
| 系统管理员 | 大模型服务不可用 | 系统自动降级到备用厂商，仍能返回回复 |

## 功能需求

### 1. 依赖注入

- `wechat.Handler` 结构体需要持有 `llm.Client` 指针
- `NewHandler` 需要接收 `llm.Client` 作为参数
- `routes.SetupRouter` 创建处理器时注入配置好的 `llm.Client`

### 2. 消息处理流程修改

原流程：所有消息返回固定文本 **"客服在开发中，敬请期待"**

新流程：
```
用户消息 → 解析 XML → 构造对话消息 → 调用 llm.Client.ChatCompletion → 获取回复 → 包装 XML 返回
```

### 3. 对话消息构造

- 构造对话历史：当前用户消息作为 `user` 角色
- （后续会增加记忆检索融入上下文，当前只传入单轮）
- 调用大模型生成回复

### 4. 错误处理

- 大模型调用失败 → 返回固定提示"服务暂时不可用，请稍后再试"
- 所有厂商都失败 → 返回固定提示

### 5. 非文本消息处理策略

所有消息类型统一调用大模型，但根据消息类型构造不同的提示词：

- **文本消息**：直接使用用户消息内容作为 `user` 角色
- **图片消息**：构造 `{Role: "user", Content: "用户发送了一张图片"}`
- **语音消息**：构造 `{Role: "user", Content: "用户发送了一条语音消息"}`
- **视频/小视频/位置/链接消息**：类似策略，提示大模型消息类型
- **订阅事件（subscribe）**：构造欢迎提示词，调用大模型生成欢迎语
- **取消订阅（unsubscribe）/ 视图事件（VIEW）**：不回复消息

### 6. 系统提示词配置

- 默认系统提示词："你是一个友好的智能客服助手，请用简洁的中文回应用户的问题。"
- 当前硬编码在代码中，后续版本可迁移到配置文件

### 7. 回复长度截断（后续优化）

- 大模型回复超过 2000 字符时，自动截断并添加"..."
- 记录警告日志

## 非功能需求

- 保持原有对所有消息类型的支持（文本、图片、语音、事件等）
- 超时控制由大模型客户端已经处理，这里不需要重复处理
- 记录调用日志
