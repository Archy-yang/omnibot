## 二、需求背景与目标

### 2.1 现状

- 当前系统采用**系统级 LLM 配置**，所有用户共用一套配置（支持 OpenAI/豆包/通义千问）
- 用户体系一期已完成（微信用户自动创建）
- 所有用户对话统一使用系统默认模型

### 2.2 问题

1. **能力受限**：系统模型无法满足部分用户的特殊需求（如：需要 GPT-4、需要用私有部署模型）
2. **资源浪费**：用户已有第三方 API Key，无法在我们系统使用
3. **生态不兼容**：无法支持兼容 OpenAI API 格式的开源模型（Ollama、vLLM、One API 等）

### 2.3 目标

> 让用户可以配置自己的 OpenAI 兼容大模型地址和密钥，对话时优先使用用户自己的配置。

### 2.4 核心设计原则

1. **渐进式交付**：先做最小可用验证需求，再优化体验
2. **优雅降级**：用户配置有问题时不阻断使用（回退到系统默认或友好提示）
3. **安全优先**：敏感信息（API Key）必须加密存储、脱敏展示

## 五、详细功能设计

### 5.1 V1.0：对话式配置

#### 命令定义

| 命令 | 功能 | 示例 |
|------|------|------|
| `#模型设置` | 进入配置引导菜单 | |
| `#设置Key sk-xxxx` | 直接设置 API Key | `#设置Key sk-abcd1234` |
| `#设置地址 https://...` | 直接设置 API 地址 | `#设置地址 https://api.openai.com/v1` |
| `#我的配置` | 查看当前配置（Key 脱敏） | |
| `#重置模型` | 清除用户配置，回退到系统默认 | |

#### 配置引导流程

```
用户：#模型设置

系统：
🔧 模型设置

请回复数字选择操作：
1️⃣ 设置 API Key
2️⃣ 设置 API 地址
3️⃣ 查看当前配置
4️⃣ 重置为系统默认

━━━━━━━━━━━━━━━━
当前状态：使用系统默认模型
```

```
用户：1

系统：请发送你的 API Key（格式：sk-开头）

用户：sk-abcdefg123456...

系统：✅ API Key 设置成功！
当前配置：
- API Key：sk-ab...56（已脱敏）
- API 地址：默认（OpenAI 官方）
- 状态：✅ 使用你的自定义配置
```

#### 配置优先级与 Fallback

```
对话请求
    ↓
用户是否有自定义配置？
    ├─ 有 → 使用用户配置发起 LLM 调用
    │      ├─ 成功 → 返回结果
    │      └─ 失败（401/404/超时等）
    │              ↓
    │        返回友好错误提示：
    │        ❌ 模型调用失败，请检查你的 API Key 或地址配置。
    │        发送「#模型设置」可重新配置
    │
    └─ 无 → 使用系统默认配置
```

### 5.2 V1.1：H5 配置页面

#### 入口流程

```
用户点击微信菜单「我的模型」
    ↓
打开 H5 页面 URL：https://your-domain.com/llm-config?token=xxx
    ↓
token 为用户 OpenID 加密（AES 加密 + 5分钟有效期）
    ↓
后端验证 token，识别用户身份，加载配置
    ↓
展示配置页面
```

#### 页面设计

```
┌─────────────────────────────┐
│      🤖 我的模型设置        │
├─────────────────────────────┤
│                             │
│  ○  使用系统默认模型        │
│                             │
│  ◉  使用我的自定义模型      │
│                             │
│  ┌───────────────────────┐ │
│  │ API Key               │ │
│  │ sk-ab...fg            │ │
│  └───────────────────────┘ │
│  [ 显示 / 隐藏 ]           │
│                             │
│  ┌───────────────────────┐ │
│  │ API 地址（可选）       │ │
│  │ https://api.openai... │ │
│  └───────────────────────┘ │
│  * 不填则使用 OpenAI 官方   │
│                             │
│  ┌───────────────────────┐ │
│  │ 默认模型（可选）       │ │
│  │ gpt-3.5-turbo         │ │
│  └───────────────────────┘ │
│                             │
│        ┌────────┐          │
│        │  保存  │          │
│        └────────┘          │
│                             │
│  [ 清除我的配置，使用默认 ] │
│                             │
└─────────────────────────────┘
```

#### 页面特性

1. **单选切换**：「使用系统默认」/「使用我的自定义模型」二选一
2. **表单联动**：选自定义时才展开 Key/地址/模型输入框
3. **明文切换**：API Key 输入框支持显示/隐藏（小眼睛图标）
4. **实时校验**：输入即时校验格式（Key 必须 `sk-` 开头、地址必须是合法 URL）
5. **脱敏回显**：加载页面时 API Key 只显示前后 3 位
6. **保存反馈**：保存成功/失败有明确的 Toast 提示

## 六、数据模型（产品层面）

### 用户 LLM 配置表

| 字段 | 说明 | 必填 | 默认值 |
|------|------|------|--------|
| 用户标识 | 关联用户 | ✅ | - |
| API Key | 加密存储 | ✅ | null |
| API 地址 | 自定义接口地址 | ❌ | OpenAI 官方 |
| 默认模型 | 调用时使用的模型名 | ❌ | gpt-3.5-turbo |
| 配置状态 | 启用/禁用 | - | 启用 |
| 创建时间 | - | - | - |
| 更新时间 | - | - | - |

### 配置状态说明

- **未设置**：用户从未配置过 → 使用系统默认
- **已设置**：用户有配置 → 使用用户配置
- **已禁用**：用户有配置但被管理员禁用 → 使用系统默认（预留）

## 七、异常与边界处理

| 场景 | 处理方式 |
|------|----------|
| **用户配置的 API Key 无效**（401） | 返回：❌ 模型调用失败，API Key 无效。请发送「#模型设置」重新配置 |
| **API 地址访问失败**（404/超时） | 返回：❌ 模型服务访问失败，请检查 API 地址配置。发送「#模型设置」可修改 |
| **用户配置了 Key 但没配置地址** | 自动使用 OpenAI 官方地址作为默认 |
| **用户配置了地址但没配置 Key** | 保存时提示：请先设置 API Key |
| **配置格式错误**（Key 不是 sk- 开头） | 返回：❌ 格式错误，API Key 必须以 sk- 开头 |
| **网络超时** | 返回：模型服务响应超时，请稍后再试或检查地址配置 |
| **配额不足**（429） | 返回：❌ 模型调用次数已达上限，请检查你的 API 配额 |
| **H5 token 过期** | 提示：链接已过期，请从微信菜单重新打开 |

## 八、非功能需求

| 项 | 要求 |
|----|------|
| **安全性** | API Key 必须 AES 加密存储，数据库中不能明文；返回前端脱敏显示（只显示前后 3 位） |
| **性能** | 用户配置查询 < 5ms，不影响对话响应时间 |
| **可观测** | 统计面板区分：系统模型调用量 / 用户自定义模型调用量 / 调用失败率 |
| **兼容性** | 兼容所有 OpenAI API 格式的服务（Azure OpenAI、One API、Ollama 等） |
| **隐私** | 用户配置数据仅用户自己可见，管理员不可查看（或需审计） |

2. **服务层**：新增用户配置管理服务（CRUD + 加密）

4. **微信 Handler**：新增配置相关的命令处理

### 不影响的模块

## 十一、风险与应对

| 风险 | 影响 | 应对措施 |
|------|------|----------|
| 用户不会配置/配置错误率高 | 体验差 | 1. 提供详细配置指南 2. V1.1 尽快上线 H5 页面降低门槛 |
| 用户滥用（用我们服务刷他自己的 Key） | 系统资源消耗 | 配置调用限流（如：每分钟 60 次） |
| 加密密钥丢失 | 所有用户配置失效 | 加密密钥多备份，不允许随意变更 |
