## 二、需求背景与目标

### 2.1 背景

v2.1 让用户拥有了邮箱密码注册的真实账号。但目前飞书入口还是"各管各的":
用户在飞书跟机器人聊天,系统会**自动为这个飞书号单独建一个账号**,与他在 web
注册的账号是两个互不相干的身份。

结果是:用户在 web 配好的模型、记下的长期记忆、聊过的历史,在飞书里看不到、用不上。
两个入口的"同一个人"被当成两个人。

v2.0 的核心是「无论从哪个入口,都是同一个 OmniBot」。要兑现这一点,必须让用户能把
自己的飞书号**绑定**到 web 账号上,绑定后飞书和 web 共享同一份身份与数据。

### 2.2 为什么是"绑定"而不是"飞书也能注册"

产品定位已确认(见 v2.1):**Web 是唯一的账号注册入口**。飞书、微信不独立创建账号,
只能绑定到已有的 web 账号。原因:

- 飞书企业自建应用的服务范围**仅限本企业内成员**,无法对所有人开放注册
- 账号体系需要一个统一、稳定的注册入口(邮箱),避免身份分裂

### 2.3 目标

> 让用户能把自己的飞书号绑定到已注册的 OmniBot 账号上。绑定后,在飞书里与机器人
> 对话,使用的就是 web 账号的身份——共享同一份对话历史、长期记忆和模型配置。

## 三、产品范围

### 3.1 本期 v2.2 做什么

1. **生成绑定码**:已登录用户在 web 端可获取一个绑定码
2. **飞书发码绑定**:用户在飞书向机器人发送绑定码,完成飞书号与 web 账号的关联
3. **绑定后身份统一**:绑定后,飞书对话使用 web 账号身份,数据互通
4. **未绑定引导**:未绑定的飞书号发消息时,机器人回复引导其先去 web 绑定
5. **绑定冲突处理**:对"飞书号已被别人绑""我的账号已绑过飞书"等情况给出明确提示

### 3.2 本期 v2.2 不做什么

1. ❌ 解绑(本期只做绑定,解绑留后续)
2. ❌ 一个账号绑定多个飞书号(本期一个账号只绑一个飞书号)
3. ❌ 换绑 / 覆盖已有绑定(账号已绑过就拒绝,需等后续解绑功能)
4. ❌ 微信账号绑定(留后续,本期只做飞书)
5. ❌ 扫码绑定(本期用绑定码,不做二维码)
6. ❌ 让企业外用户使用飞书(受飞书企业应用限制,非本期能解决)
7. ❌ web 端实时显示绑定状态变化(绑定成功在飞书端反馈即可;web 端下次进入时能看到)

### 3.3 与现有能力的关系

- 绑定后,飞书端复用已有的对话、Agent、长期记忆、模型配置能力,这些功能本身不变,
  只是身份从"飞书独立账号"变为"已绑定的 web 账号"
- **现有飞书行为变更**:在本期之前,飞书消息会自动建号;本期之后,未绑定的飞书号
  **不再自动建号**,而是收到绑定引导(见 5.4)
- web 微信入口不受本期影响

## 四、字段与规则约定

为避免理解歧义,本期绑定相关规则统一约定如下,功能描述与验收均以此为准。

### 4.1 绑定码规则

| 项 | 规则 |
|----|------|
| 格式 | **6 位纯数字** |
| 有效期 | 生成后 **5 分钟**内有效,过期作废 |
| 归属 | 绑定码与生成它的 web 账号绑定,只能用于绑定到该账号 |
| 失效 | 绑定成功后立即失效;过期后失效;重新生成后旧码失效 |
| 重复获取 | 用户可重复获取;每次获取生成新码,旧码作废 |

### 4.2 绑定关系规则

| 项 | 规则 |
|----|------|
| 数量 | 一个 web 账号**最多绑定一个飞书号**;一个飞书号最多绑定一个 web 账号 |
| 账号已绑 | 若当前账号已绑过飞书号,再用新码绑另一个飞书号 → **拒绝**(本期不支持换绑) |
| 飞书号已绑 | 若目标飞书号已绑到别的账号 → **拒绝**(防一号多账号) |

### 4.3 飞书发送绑定码格式

| 项 | 规则 |
|----|------|
| 发送格式 | 用户在飞书向机器人发送 **`绑定 ` + 绑定码**(动作词「绑定」+ 一个空格 + 6 位码),例如 `绑定 123456` |
| 识别规则 | 仅当消息匹配「绑定 + 空格 + 6 位数字」格式时,才作为绑定请求处理 |
| 不匹配 | 不符合该格式的消息,按普通对话或未绑定引导处理(见 5.4) |

## 五、功能描述

### 5.1 web 端获取绑定码

- 已登录用户在 web 端的设置 / 账号区域,可看到「绑定飞书」入口
- 点击后:
  - 若当前账号**未绑定**飞书:展示一个 6 位绑定码 + 有效期倒计时(5 分钟)+ 飞书侧操作说明
    (提示用户:在飞书向机器人发送「绑定 + 空格 + 该码」)
  - 若当前账号**已绑定**飞书:不展示绑定码,而是展示「已绑定飞书」状态(本期不提供解绑)
- 用户可重新获取绑定码(旧码立即作废)

### 5.2 飞书端提交绑定码

用户在飞书向机器人发送 `绑定 123456`,系统按以下情况处理:

| 情况 | 结果(飞书端回复) |
|------|--------------------|
| 码有效 + 飞书号未被占用 + 该码对应账号未绑过飞书 | 绑定成功,回复「绑定成功!现在可以在飞书跟我聊了」 |
| 码不存在 / 已过期 | 回复「绑定码无效或已过期,请在 web 端重新获取」 |
| 该飞书号已绑到其他账号 | 回复「该飞书号已绑定其他账号」 |
| 该码对应的 web 账号已绑过飞书号 | 回复「你的账号已绑定飞书,如需更换请稍后(暂不支持)」 |

### 5.3 绑定后的身份统一

- 绑定成功后,该飞书号的后续对话,使用所绑定 web 账号的身份
- 飞书端能用上该账号在 web 配置的模型、已存的长期记忆、对话历史
- 在 web 与飞书任一端产生的对话和记忆,另一端登录 / 使用时都能看到(同一账号)

### 5.4 未绑定飞书号的处理

- 未绑定任何账号的飞书号给机器人发消息时:
  - **不自动创建账号**
  - 机器人回复**详细引导**(含操作步骤),内容大意:
    > 你还没有绑定 OmniBot 账号。请先在 web 端登录,在设置里获取绑定码,然后在这里
    > 发送「绑定 + 空格 + 绑定码」(例如 `绑定 123456`)完成绑定。
- 引导回复后不进行对话处理(未绑定不能直接聊天)

### 5.5 web 端绑定入口页面

- 在设置 / 账号区域提供「飞书绑定」区块
- 未绑定状态:获取绑定码按钮 → 展示码 + 倒计时 + 飞书侧操作说明
- 已绑定状态:显示「已绑定飞书」
- 视觉风格与 v2.0 设计保持一致

## 六、交互流程

### 6.1 绑定主流程

```
web 端(已登录)→ 设置 → 点「获取飞书绑定码」
   ├─ 账号已绑飞书 → 显示「已绑定飞书」,不出码
   └─ 账号未绑 → 生成 6 位码(5 分钟有效)+ 操作说明
                      ↓
用户打开飞书 → 向机器人发送「绑定 123456」
                      ↓
系统校验:
   ├─ 码无效/过期 → 回复「绑定码无效或已过期,请在 web 端重新获取」
   ├─ 飞书号已绑其他账号 → 回复「该飞书号已绑定其他账号」
   ├─ 该账号已绑过飞书 → 回复「你的账号已绑定飞书,如需更换请稍后(暂不支持)」
   └─ 全部通过 → 建立绑定 → 码失效 → 回复「绑定成功!现在可以在飞书跟我聊了」
```

### 6.2 未绑定用户发消息

```
飞书号给机器人发消息(非绑定码格式)
   ├─ 该飞书号已绑定 → 正常进入对话(用绑定账号身份)
   └─ 该飞书号未绑定 → 不建号,回复详细绑定引导
```

## 七、非功能需求

### 7.1 安全

- 绑定码有效期短(5 分钟),降低被猜中 / 滥用风险
- 绑定码与账号强关联,一个码只能绑到生成它的账号
- 同一飞书号不能同时绑定多个账号,防止身份冒用
- 错误提示不暴露系统内部细节,不泄露其他账号信息(如不显示"该飞书号绑定的是哪个账号")

### 7.2 体验

- web 端绑定码展示清晰,带有效期提示和飞书侧操作说明,用户知道下一步做什么
- 飞书端各种绑定结果都有明确回复,用户不会"发了没反应"
- 未绑定引导明确告知操作步骤,而不是简单拒绝

### 7.3 可靠性

- 绑定操作幂等:同一码重复提交,已绑定后不会重复建立绑定或报错混乱
- 并发场景下,同一飞书号 / 同一账号不会产生重复或冲突的绑定关系

## 八、验收标准

### 8.1 功能验收

- [ ] 已登录用户能在 web 端获取 6 位绑定码,带 5 分钟有效期提示
- [ ] 用户在飞书发送「绑定 + 空格 + 有效码」绑定成功,飞书端回复「绑定成功!现在可以在飞书跟我聊了」
- [ ] 绑定成功后,飞书对话使用 web 账号身份,能看到该账号的长期记忆和模型配置
- [ ] 绑定成功后,在 web 与飞书任一端的新对话 / 新记忆,另一端可见
- [ ] 绑定码过期(超过 5 分钟)后提交,回复「绑定码无效或已过期,请在 web 端重新获取」
- [ ] 重新获取绑定码后,旧码失效
- [ ] 目标飞书号已绑其他账号时,回复「该飞书号已绑定其他账号」,不建立绑定
- [ ] 当前账号已绑过飞书号时,再用新码绑另一个飞书号被拒绝,回复对应提示
- [ ] 未绑定飞书号发消息时,**不自动建号**,回复含操作步骤的绑定引导
- [ ] 未绑定飞书号发的消息不进入正常对话处理
- [ ] 账号已绑定飞书时,web 端绑定区显示「已绑定飞书」,不再出码

### 8.2 安全验收

- [ ] 绑定码 5 分钟后失效
- [ ] 一个绑定码只能用于绑定到生成它的账号
- [ ] 同一飞书号不能绑定到多个账号
- [ ] 错误提示不泄露其他账号信息

### 8.3 体验验收

- [ ] web 端绑定码展示含有效期与飞书操作说明
- [ ] 飞书端每种绑定结果都有明确回复
- [ ] 未绑定引导含明确操作步骤
