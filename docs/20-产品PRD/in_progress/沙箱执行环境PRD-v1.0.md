## 1. 需求背景与目标

### 背景

助手的执行能力目前全部来自硬编码工具（天气、网页抓取、飞书 CLI 等）。遇到"帮我处理这份数据 / 做个格式转换 / 验证这段逻辑"类需求时，Agent 只能口头引导用户自己操作，或退化为逐条计算。

同时，Skill 系统（prompt + 工具组合的能力包）已在技术规划中留白，其中的"可选脚本"部分需要一个安全的代码执行底座。

### 目标

1. Agent 能在受控沙箱中执行 Python/Shell 脚本，完成数据处理、格式转换、计算验证类任务
2. **安全是第一约束**：LLM 生成的代码不可信，沙箱必须保证脚本碰不到宿主数据（记忆、配置、密钥）、无法外传数据、无法拖垮宿主
3. 为 Skill（含脚本的指令包）提供可复用的执行底座

### 非目标（本期）

- 脚本产物文件（CSV/图片等）的存储与投递——结果只以 stdout/stderr 文本回传
- 常驻执行环境 / 交互式 REPL
- 联网执行（首期断网）
- 用户自定义持久化脚本工具

## 2. 用户故事

| # | 故事 | 验收要点 |
|---|------|---------|
| U1 | 作为用户，我让助手"把这串 JSON 转成表格"，助手在沙箱里跑脚本完成转换，把结果直接回在对话里 | 结果来自沙箱执行，非 LLM 幻觉；对话流内可见执行产出 |
| U2 | 作为用户，我让助手"算一下这组数据的平均值和标准差"，得到精确结果 | 数值计算精确（非 LLM 心算） |
| U3 | 作为用户，我在设置的工具清单里看到"沙箱执行"开关，可以停用它 | 开关即时生效，无需重启 |
| U4 | 作为用户，脚本失控（死循环/吃内存）时，宿主机不受影响，任务正常失败并告知我 | 限额生效，失败信息可读 |
| U5 | 作为用户，Docker 没启动时，助手告诉我原因和怎么恢复，而不是报一堆内部错误 | 引导文案可读，启动 Docker 后自愈 |

## 3. 功能描述

1. 新增内置工具 `sandbox_run`（子 Agent 专属，主 Agent 经 delegate 派活使用）：
   - 输入：执行命令（argv 数组）、可选输入文件、可选 stdin、可选超时
   - 输出：退出码 + stdout + stderr（文本，有截断上限）
2. 执行环境：一次性 Docker 容器——默认断网、文件系统只读、非 root、内存/CPU/进程数/时长四重限额
3. 每次执行的工作目录独立，执行结束即销毁，不残留状态
4. 工具遵循现有工具体系：定义落 `tools` 表（可启停）、设置页工具清单可见

## 4. 交互流程

```
用户提出数据处理类请求（Web/飞书/微信）
  → 主 Agent 判定需要跑代码 → delegate 派活给子 Agent
  → 子 Agent 调用 sandbox_run（构造脚本+数据文件）
  → 沙箱执行（断网/限额/一次性）
  → stdout/stderr 回传 → 子 Agent 汇总 → 主 Agent 汇报
  → 用户在对话中看到结果
```

异常路径：
- Docker 不可用 → 引导文案（启动 Docker 后重试即可，免重启服务）
- 超时/超限 → 明确告知"脚本超时/超出资源限额被终止"
- 输出超限 → 截断回传并提示截断发生

## 5. 验收标准

| # | 标准 |
|---|------|
| A1 | 脚本无法访问网络（`--network none`，live 测试断言 socket 失败） |
| A2 | 脚本无法写 rootfs（只读，live 测试断言写系统路径被拒） |
| A3 | 宿主环境变量不出现在沙箱内（env 隔离，测试断言） |
| A4 | 超时/内存/PID 限额生效（测试断言，live 断言超时被杀） |
| A5 | 输出超过上限被截断，回传可读 |
| A6 | 执行结束容器与 scratch 目录均被清理（测试断言清理调用幂等） |
| A7 | argv 直传不经 shell（注入类输入不产生 shell 解释） |
| A8 | 工具可在设置中启停，停用即时生效 |
| A9 | Docker 缺失时给出引导文案；恢复后无需重启服务 |
| A10 | 日志不包含脚本内容与输出全文（安全红线） |

## 6. 非功能需求

- **安全**：见验收 A1~A7/A10；隔离级别为容器级（共享内核已知限制记录在案），远程部署可切 gVisor 加固（配置位预留）
- **性能**：单次执行冷启动（含容器创建）目标 < 2s（不含脚本本身运行时间）
- **兼容**：macOS（Docker Desktop）与 Linux 服务器同一份代码，行为一致
- **可观测**：每次执行记结构化元数据（时长/退出码/输出字节数/是否截断/是否超时）

## 7. 埋点需求

不适用（单用户自部署产品，无行为埋点体系）；以结构化日志代替。
