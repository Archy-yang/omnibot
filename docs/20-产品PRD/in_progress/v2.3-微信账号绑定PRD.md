## 二、需求背景与目标

### 2.1 背景

v2.2 让飞书号能绑定到 web 账号,兑现了"飞书和 web 是同一个人"。但**微信入口还在自动建号**--
用户在微信跟机器人聊天,系统仍会单独建一个账号,与 web 账号互不相干。

v2.0 愿景是「无论从哪个入口,都是同一个 OmniBot」。飞书绑定了,微信没绑定,这条愿景就只兑现了一半。
v2.3 把微信入口也切到绑定模型,让"全平台单一身份"真正成立。

### 2.2 目标

> 让用户能把自己的微信号绑定到已注册的 OmniBot 账号上。绑定后,在微信里与机器人对话,
> 使用的就是 web 账号的身份--共享同一份对话历史、长期记忆和模型配置。

### 2.3 与 v2.2 的关系

v2.3 是 v2.2 的对称延伸,产品规则几乎完全复用,差异仅在微信入口的交互模式适配。
**一个 web 账号可同时绑定飞书和微信**(不同渠道各一个),用户在三个入口都是同一身份。

## 三、产品范围

### 3.1 本期 v2.3 做什么

1. **微信端提交绑定码**:用户在微信向机器人发送绑定码,完成微信号与 web 账号的关联
2. **绑定后身份统一**:绑定后,微信对话使用 web 账号身份,数据互通
3. **未绑定引导**:未绑定的微信号发消息时,机器人回复引导其先去 web 绑定(不自动建号)
4. **关注事件引导**:新用户关注公众号时,不建号,回复欢迎语 + 绑定引导
5. **绑定冲突处理**:复用 v2.2 规则(微信号已绑别的账号 / 账号已绑过微信)

### 3.2 本期 v2.3 不做什么

1. ❌ 解绑 / 换绑(与 v2.2 一致,留后续)
2. ❌ 一个账号绑定多个微信号(本期一个账号只绑一个微信号)
3. ❌ 微信扫码绑定(用绑定码,不做二维码)
4. ❌ 企业微信 / 微信小程序(本期只做公众号)
5. ❌ web 端实时显示微信绑定状态变化(绑定成功在微信端反馈即可)

### 3.3 现有微信行为变更

| 行为 | v2.3 之前 | v2.3 之后 |
|------|-----------|-----------|
| 未绑微信号发普通消息 | 自动建号 + 回复 | **不建号**,回绑定引导 |
| 关注公众号 | 自动建号 + 欢迎语 | **不建号**,回欢迎语 + 绑定引导 |
| 已绑微信号发消息 | 用自动建的号 | 用绑定的 web 账号身份 |
| `#模型设置` 等命令 | 任何用户可用 | 仅已绑定用户可用(未绑回引导) |

## 四、字段与规则约定

### 4.1 绑定码规则(复用 v2.2)

| 项 | 规则 |
|----|------|
| 格式 | 6 位纯数字 |
| 有效期 | 生成后 5 分钟内有效 |
| 归属 | 绑定码与生成它的 web 账号绑定 |
| 失效 | 绑定成功后立即失效;过期后失效;重新生成后旧码失效 |
| **渠道通用** | **一个码不区分渠道,在飞书或微信发送都能绑定到对应渠道**(v2.3 新增) |

> 说明:用户在 web 出一个码后,在飞书发就绑飞书,在微信发就绑微信。码只用一次,绑定成功即作废。
> 想同时绑飞书和微信,需要出两次码(每次绑一个渠道)。

### 4.2 绑定关系规则

| 项 | 规则 |
|----|------|
| 数量 | 一个 web 账号**最多绑定一个飞书号 + 一个微信号**(不同渠道各一个) |
| 微信号已绑 | 若该微信号已绑到别的账号 -> 拒绝 |
| 账号已绑微信 | 若当前账号已绑过微信号 -> 拒绝(本期不支持换绑) |
| 跨渠道 | 绑飞书不影响绑微信,反之亦然 |

### 4.3 微信发送绑定码格式(复用 v2.2)

| 项 | 规则 |
|----|------|
| 发送格式 | `绑定 ` + 绑定码(动作词「绑定」+ 一个空格 + 6 位码),例如 `绑定 123456` |
| 识别规则 | 仅当消息匹配「绑定 + 空格 + 6 位数字」格式时,才作为绑定请求处理 |
| 与命令冲突 | 微信命令用 `#` 前缀(如 `#模型设置`),绑定码不带 `#`,无冲突 |

## 五、功能描述

### 5.1 微信端提交绑定码

用户在微信向机器人发送 `绑定 123456`,系统按以下情况处理(复用 v2.2 文案):

| 情况 | 结果(微信端回复) |
|------|--------------------|
| 码有效 + 微信号未被占用 + 该码对应账号未绑过微信 | 绑定成功,回复「绑定成功!现在可以在微信跟我聊了」 |
| 码不存在 / 已过期 | 回复「绑定码无效或已过期,请在 web 端重新获取」 |
| 该微信号已绑到其他账号 | 回复「该微信号已绑定其他账号」 |
| 该码对应的 web 账号已绑过微信号 | 回复「你的账号已绑定微信,如需更换请稍后(暂不支持)」 |

### 5.2 绑定后的身份统一

- 绑定成功后,该微信号的后续对话,使用所绑定 web 账号的身份
- 微信端能用上该账号在 web 配置的模型、已存的长期记忆、对话历史
- 在 web / 飞书 / 微信任一端产生的对话和记忆,其他端登录/使用时都能看到(同一账号)

### 5.3 未绑定微信号的处理

- 未绑定任何账号的微信号给机器人发消息时(非绑定码格式):
  - **不自动创建账号**
  - 机器人回复**详细引导**,内容大意:
    > 你还没有绑定 OmniBot 账号。请先在 web 端登录,在设置里获取绑定码,然后在这里
    > 发送「绑定 + 空格 + 绑定码」(例如 `绑定 123456`)完成绑定。
  - 引导回复后不进行对话处理(未绑定不能直接聊天)

### 5.4 关注事件的处理

- 新用户关注公众号时:
  - **不自动建号**
  - 回复欢迎语 + 绑定引导,内容大意:
    > 欢迎关注 OmniBot!你还没有绑定账号,请先在 web 端登录并获取绑定码,然后发送
    > 「绑定 + 空格 + 绑定码」完成绑定,绑定后我们就可以聊天啦。
- 已绑定的用户重新关注(取关后再关注):不特殊处理,正常回欢迎语

### 5.5 web 端绑定入口

- v2.2 的「飞书绑定」区块扩展为「渠道绑定」区块:
  - 同时展示飞书绑定状态 + 微信绑定状态
  - 绑定码通用,一个码两个渠道都能用
  - 操作说明改为"在你要绑定的渠道(飞书或微信)发送:绑定 <码>"

## 六、交互流程

### 6.1 微信绑定主流程

```
web 端(已登录)-> 设置 -> 点「获取绑定码」
   ├─ 账号已绑飞书+微信 -> 显示两个「已绑定」,不出码
   ├─ 账号已绑飞书、未绑微信 -> 仍可出码(用于绑微信)
   └─ 出码 + 操作说明「在飞书或微信发送:绑定 <码>」
                      ↓
用户打开微信 -> 向机器人发送「绑定 123456」
                      ↓
系统校验(5 秒内返回 XML):
   ├─ 码无效/过期 -> 回复「绑定码无效或已过期,请在 web 端重新获取」
   ├─ 微信号已绑其他账号 -> 回复「该微信号已绑定其他账号」
   ├─ 该账号已绑过微信 -> 回复「你的账号已绑定微信,如需更换请稍后(暂不支持)」
   └─ 全部通过 -> 建立绑定 -> 码失效 -> 回复「绑定成功!现在可以在微信跟我聊了」
```

### 6.2 未绑定用户发消息

```
微信号给机器人发消息(非绑定码格式)
   ├─ 该微信号已绑定 -> 正常进入对话(用绑定账号身份)
   └─ 该微信号未绑定 -> 不建号,回复详细绑定引导
```

## 七、非功能需求

### 7.1 安全

- 复用 v2.2 全部安全规则(绑定码 5 分钟过期、一码一账号、不泄露其他账号信息)
- 微信被动回复 5 秒超时内完成绑定操作(DB 读写绰绰有余)

### 7.2 体验

- 微信端各种绑定结果都有明确回复(5 秒内),用户不会"发了没反应"
- 关注事件回欢迎语 + 引导,新用户知道下一步做什么
- 未绑定引导明确告知操作步骤

### 7.3 可靠性

- 复用 v2.2 幂等保证(同码重复提交不重复建绑定)
- 并发场景下,同一微信号 / 同一账号不会产生重复绑定

## 八、验收标准

### 8.1 功能验收

- [ ] 用户在微信发送「绑定 + 空格 + 有效码」绑定成功,回复「绑定成功!现在可以在微信跟我聊了」
- [ ] 绑定成功后,微信对话使用 web 账号身份,能看到该账号的长期记忆和模型配置
- [ ] 绑定成功后,在 web / 飞书 / 微信任一端的新对话/新记忆,其他端可见
- [ ] 一个账号能同时绑飞书 + 微信,两个渠道都能用
- [ ] 绑定码过期后提交,回复「绑定码无效或已过期,请在 web 端重新获取」
- [ ] 目标微信号已绑其他账号时,回复「该微信号已绑定其他账号」
- [ ] 账号已绑过微信时,再用新码绑另一个微信号被拒绝
- [ ] 未绑微信号发普通消息时,不自动建号,回复含操作步骤的绑定引导
- [ ] 新用户关注公众号时,不建号,回复欢迎语 + 绑定引导
- [ ] 未绑微信号发 `#模型设置` 等命令,不执行命令,回绑定引导
- [ ] web 端绑定区同时展示飞书 + 微信状态,绑定码通用

### 8.2 安全验收

- [ ] 复用 v2.2 全部安全项(码 5 分钟失效、一码一账号、不泄露其他账号)
- [ ] 微信绑定操作在 5 秒超时内完成

### 8.3 体验验收

- [ ] 微信端每种绑定结果都有明确回复
- [ ] 关注事件回复含欢迎语 + 绑定操作步骤
- [ ] web 端绑定码展示含两个渠道的操作说明
