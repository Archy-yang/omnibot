## 1. 背景与问题

v2.3 的「微信」通道是**微信公众号**：需要用户关注公众号、在后台配置回调 URL、被动回复受 5 秒限制。
个人用户日常真正高频的入口是**微信个人号**，而公众号没法覆盖。

微信 2026-03 推出了 **ClawBot**（官方 OpenClaw 微信插件）：扫码授权后，微信里多出一个
「微信Claw」机器人，可以直接像聊天一样对话。官方只提供 Node 插件，但我们用 Go 原生实现了
同一套 HTTP 协议（见 31 号技术方案），因此可以把它接成 OmniBot 的又一个 IM 入口。

## 2. 目标与非目标

### 2.1 目标

1. 用户在 Web 设置页扫码，即可把微信接成 OmniBot 的对话入口。
2. 微信里发的文字消息，走与 Web/飞书**完全一致**的助手链路（上下文、记忆、工具、后台任务）。
3. 助手的回复发回微信。
4. 登录凭证加密存储；支持断开连接；进程重启后自动恢复长轮询。
5. 复用 v2.3 绑定模型：未绑定微信用户只收到引导，不自动建号。

### 2.2 非目标（本期不做）

- 图片 / 语音 / 文件 / 视频收发（CDN + AES-128-ECB + SILK 转码，二期）
- 「对方正在输入」状态
- 群聊、多账号并发、主动加好友
- 通过 ClawBot 反向发朋友圈 / 群发（合规红线）

## 4. 交互与文案

- 设置页新增左侧导航「微信接入」：
  - 未连接：一个「扫码连接微信」按钮 + 风险提示（官方 Beta、仅自己使用、凭证加密）
  - 扫码中：二维码 220×220 + 「用微信扫码并在手机上确认，Ns 后失效」倒计时
  - 需要数字校验（`need_verifycode`）：输入框 + 提交
  - 已连接：机器人 id + 「断开连接」
- 「渠道绑定」区块增加第三行「微信 ClawBot」，状态与飞书/微信并列。
- **不需要绑定码**：扫码即绑定到发起扫码的 web 账号（`BindDirect`），
  「渠道绑定」区块里微信 ClawBot 行显示「已绑定」由后端自动建立。
- 非主人微信（同一机器人被他人添加等极端情况）才回「未绑定」引导，不建号、不进对话。
- 非文本消息回执：「暂时只支持文字消息，图片/语音/文件稍后支持。」

## 5. 约束与风险

1. **合规**：ClawBot 是官方 Public Beta 的个人号通道，仅用于用户与自己的助手单聊；
   不做群发、不加群、不主动加好友。设置页需明示。
2. **凭证安全**：`bot_token` 等敏感凭证 AES-256-GCM 加密入库，日志脱敏，接口不回传。
3. **协议稳定性**：官方可能调整端点/版本头。协议层集中在 `internal/channel/wechatclaw`，
   版本号与域名可配置，改版时只动一个包。
4. **游标**：`get_updates_buf` 落库，重启续传，避免重放历史消息。
5. **单账号**：本期全库只维护一个 ClawBot 登录态。
