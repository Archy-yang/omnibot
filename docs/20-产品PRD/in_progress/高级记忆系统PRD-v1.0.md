## 二、需求背景与目标

### 2.1 背景

已交付的长期记忆 MVP 解决了「用户显式交代 + 助手记住」的问题：用户通过 `#记住` 命令或 Web 管理页主动告诉助手要记什么，助手在后续对话中参考这些记忆。

但这个模式有一个根本限制：**记住什么，完全取决于用户想不记得说**。而真实用户在对话中透露的重要信息——偏好、身份、项目背景、做过的重要决定——绝大多数时候不会专门交代。同时，时间跨度一长，「上周聊过的那个方案」「之前说过的那个偏好」这类过往对话内容，助手也找不回来。

产品愿景 v2.0 把「永远记得你」列为第一差异化价值，设计原则第一条是「记忆优先：任何功能如果和记忆冲突，优先保证记忆的正确性」。当前的记忆能力距离这个愿景还差关键一步：从「用户手动记」升级为「助手自动懂」。

### 2.2 问题

1. **该记的没记住**：用户不会每条重要信息都专门说「#记住」，大量有价值的偏好、背景、决定随对话流走。
2. **找不回聊过的**：对话一多，用户问「我们上次聊的 XX 是什么结论」，助手无法回溯更早的对话内容。
3. **记了但用不好**：现有方式是每次对话固定带入最近几条记忆，与当前话题无关的记忆占着位置，真正相关的记忆反而可能没被带入。
4. **管理入口不全**：记忆管理只在 Web 端，微信/飞书用户无法查看和清理自己的记忆。

### 2.3 目标

> 让助手自动记住对话中值得记住的信息，在需要时主动想起，并让用户随时能看到「它记住了我什么」、追溯到「它是从哪句话记住的」——形成「越聊越懂我，且一切透明可控」的体验。

## 三、产品范围

### 3.1 记忆体系的产品模型

用户视角下，助手对用户的了解分为三层，各司其职：

| 层 | 是什么 | 用户感知 |
|----|--------|---------|
| 短期记忆 | 正在进行的这轮对话 | 无需感知，天然存在 |
| 中期记忆 | 过往对话的「纪要」——某段时间我们聊过什么、聊出了什么结论 | 「它记得我们之前聊过 XX」 |
| 长期记忆 | 从对话中沉淀出的稳定事实——身份、偏好、习惯、长期项目 | 「它知道我是谁、我喜欢什么」 |

中期和长期记忆都指向产生它们的原始对话，用户可以随时查看完整来龙去脉。

### 3.2 本次做什么

**1. 自动记忆沉淀（长期记忆）**

对话过程中，助手自动识别值得长期记住的信息（如「用户是后端工程师」「用户偏好简洁的回复风格」）并沉淀为长期记忆。用户无需任何命令。

- 沉淀过程对用户透明、不打断对话；
- 每条自动沉淀的记忆用户可见，随时可查看、编辑、删除；
- 用户显式的 `#记住` 命令保持不变，与自动沉淀共存。

**2. 对话纪要（中期记忆）**

系统将过往对话按阶段整理成纪要，纪要概括「那段时间聊了什么主题、达成了什么结论」。

- 纪要自动生成，无需用户操作；
- 纪要可回溯到对应的原始对话明细。

**3. 智能回想（记忆召回）**

用户在对话中提到过往内容时，助手能主动找回相关的记忆和对话纪要并用于回答，而非只能依赖最近几条。

- 典型场景：「上次我们聊的那个方案后来怎么样了」「按我之前说的偏好来」「还记得我提过的那个项目吗」；
- 助手根据当前话题主动判断需要回想什么，用户无需使用任何特殊指令。

**4. 记忆透明与可控**

- 用户随时可以查看助手记住的全部内容（含自动沉淀的与手动交代的，两者有区分标识）；
- 每条记忆可以追溯到「从哪段对话来的」；
- 任何一条记忆都可编辑、删除；全部记忆可一键清空；
- 微信、飞书用户可以在对话中直接使用记忆管理命令（查看、删除），不再只有 Web 端能管理。

### 3.3 本次不做什么

1. 不做记忆的自动分类标签体系（本期记忆不分类展示）。
2. 不做重要性评分与置顶。
3. 不做记忆导出/备份/迁移。
4. 不做敏感信息的自动识别拦截，延续现有策略：存储时安全提示 + 内容长度限制 + 日志脱敏 + 用户全程可见可删。
5. 不做跨用户、跨账号的记忆共享或迁移。
6. 不做记忆修改的历史版本管理（编辑直接生效，保留最近修改时间）。

### 3.4 与现有能力的关系

- **短期上下文记忆**（最近 N 轮）保持不变，不在本期改动范围；
- **长期记忆 MVP**（`#记住` 命令、Web 管理页、每轮注入）全部保留；本期在其上叠加自动沉淀与智能回想能力；
- **后台 Agent 任务**：派出去的后台任务完成后，其关键结论同样遵循本期的沉淀规则（经用户确认的主流程转述后可成为记忆），本期只需保证规则不冲突，不做专门功能。

## 四、用户故事与验收标准

### US1 自动沉淀

**故事**：作为用户，我在对话中提到自己的偏好、背景或重要决定后，之后任何时候的对话中助手都自然记得，无需我再次说明或手动命令。

**验收**：
- AC1.1 对话中出现明确的长期有效信息（身份、偏好、长期项目等）后，后续对话中助手能正确使用该信息；
- AC1.2 沉淀过程不在对话中插入额外提示或打断；
- AC1.3 自动沉淀的记忆在 Web 管理页可见，与手动交代的记忆有明确区分（如来源标识）；
- AC1.4 用户删除一条自动沉淀的记忆后，后续对话不再使用它（除非再次出现）。

### US2 对话纪要

**故事**：作为用户，我隔了很长时间回来问「我们之前聊过什么」，助手能概括出过往对话的主题和结论，并给我看原始对话。

**验收**：
- AC2.1 助手能正确回答「我们最近聊过哪些话题」类问题；
- AC2.2 纪要对应的原始对话明细可回溯查看（Web 端体现为入口，渠道端体现为可按时间范围查看历史）；
- AC2.3 纪要对用户可见、可删除（删除纪要不影响原始对话明细）。

### US3 智能回想

**故事**：作为用户，我在对话中引用过往内容（哪怕是很久之前的），助手能找回相关内容并自然用于回答。

**验收**：
- AC3.1 用户询问「之前说的 XX」时，若相关信息在记忆或纪要中，助手能正确召回并回答；
- AC3.2 相关内容距当前对话较远（不在最近 N 轮内）时依然有效；
- AC3.3 找不到相关内容时，助手如实说「没有找到相关记录」，不编造。

### US4 记忆透明与可控

**故事**：作为用户，我随时知道助手记住了我什么，并能随时查看来源、修改或删除。

**验收**：
- AC4.1 Web 管理页展示全部记忆，自动沉淀的记忆带有来源标识；
- AC4.2 每条记忆可以查看其来源对话（跳转或展示对应对话片段）；
- AC4.3 微信/飞书端提供记忆管理命令：查看记忆列表（含来源标记）、按序号删除记忆；
- AC4.4 清空全部记忆的入口保持现有行为不变，且清空范围对自动沉淀记忆一致。

## 五、交互与文案要点

1. **沉淀不打扰**：自动沉淀全程静默，对话流中不出现「我记住了 XX」类系统消息（区别于显式 `#记住` 的成功回执）。
2. **如实回答**：回想不到就说找不到，禁止用泛泛的通用回答冒充「记得」。
3. **来源优先**：当记忆内容与用户当前陈述冲突时，以用户当前陈述为准，并适时更新记忆（体现「记忆正确性优先」原则）。
4. **渠道文案**：微信/飞书的记忆命令文案与现有 `#记住` 体系风格一致，命令需要易记、可发现（首次使用自动沉淀功能时，可由助手在合适时机用一句话自然告知「我会在聊天中记住重要信息，你随时可以说 #我的记忆 查看我记住了什么」）。

## 六、非功能需求

1. **记忆正确性优先**（愿景红线）：自动沉淀宁可漏记，不可错记；任何时刻用户的手动编辑/删除拥有最高优先级。
2. **隐私**：记忆内容属用户敏感数据，日志中不输出记忆原文与完整对话内容；记忆仅本人可见，任何入口不做记忆内容的外发。
3. **入口无关**：三层记忆与沉淀/回想能力对所有渠道（Web/微信/飞书）一致生效，行为无差异。
4. **性能感知**：沉淀与回想过程不得让用户可感知地拖慢对话响应。
5. **可关闭**：用户可以关闭自动沉淀（关闭后仅保留显式 `#记住`），开关在 Web 设置中提供，默认开启。

---

## 七、成功指标

1. 主观：用户重复解释自身信息的频率显著下降（可从对话中「我之前说过」类语句的出现率观察）；
2. 可用性：自动沉淀的记忆被后续对话实际引用的比例；
3. 信任：记忆管理页的访问量与编辑/删除操作分布（用户真的在看、在管）；
4. 覆盖：三入口（Web/微信/飞书）记忆行为一致性验证通过。

## 八、已决问题（2026-08-31 评审定案）

| # | 问题 | 决策 |
|---|------|------|
| 1 | 自动沉淀的触发密度 | **按对话段落批量判断**：不对每轮单独处理，而是当积累了一段对话后统一做一次纪要+提取，减少干扰与成本 |
| 2 | 渠道端「来源回溯」形态 | **时间线 + 引导 Web**：微信/飞书命令返回记忆内容 + 来源时间线索（哪天、大致话题），完整对话明细引导到 Web 管理页查看 |
| 3 | 自动沉淀开关默认值 | **默认开启**（这是本期的核心价值）；首次沉淀发生时由助手用一句话自然告知可关闭 |
