## 一、概述

本次迭代在 v1.3 长期记忆 MVP 基础上，新增了单条记忆删除/编辑、Web 端记忆管理 UI、以及 SSE 流式对话输出三项核心能力。

---

## 二、新增功能

### 2.1 单条记忆删除与编辑

**微信命令：**
- `#删除记忆 N` — 按序号删除第 N 条记忆
- 序号无效时提示正确用法
- 服务异常时返回统一错误文案

**Web API：**
- `DELETE /api/v1/memories/:id` — 删除指定记忆
- `PUT /api/v1/memories/:id` — 更新指定记忆内容

**后端架构：**
- Repository 新增 `GetByID`、`DeleteByID`、`UpdateContentByID`
- Service 新增 `Delete`、`Update`（含空内容/超长校验）
- 所有操作按 `user_id + id` 双重校验，保证用户隔离

**测试覆盖：** 21 个新测试（Repository 9 + Service 7 + Web Handler 5）

### 2.2 Web 端记忆管理 UI

在设置面板的记忆区域，每条记忆现在支持：

- **删除**：点击删除按钮，弹出确认对话框，确认后删除
- **编辑**：点击编辑按钮，内联切换为输入框，支持保存/取消
- 输入校验：空内容提示、200 字上限限制
- 操作反馈：成功/失败 toast 提示

**前端改动链路：**
```
types/api.ts → services/memory.ts → stores/memory.ts → composables/useMemory.ts → MemorySection.vue
```

### 2.3 SSE 流式对话输出

将 Web 对话从「等待完整响应后一次性返回」改为「打字机式逐字流式输出」。

**后端：**
- LLM Client 接口新增 `StreamChatCompletion`，返回 `<-chan StreamChunk`
- OpenAI Provider 实现：`stream: true` + `bufio.Scanner` 逐行解析 SSE → channel
- Doubao / Qwen Provider 暂返回 `ErrStreamingNotSupported`
- 新增 `POST /api/v1/chat/messages/stream` SSE 端点
- 响应头 `Content-Type: text/event-stream`，每收到一个 chunk 立即 Flush

**前端：**
- `chatService.sendMessageStream` — 使用原生 `fetch` + `ReadableStream` 读取 SSE
- Chat Store `sendMessage` 改为流式：创建占位 assistant 消息，逐 chunk 追加内容
- 流式过程中 `isLoading` 保持 true，UI 自动显示打字效果

**降级策略：**
- 现有 `POST /api/v1/chat/messages` 同步端点保留不变
- 流式失败时 store 移除占位消息并抛出错误
- 非 OpenAI provider 用户继续使用同步端点

**测试覆盖：** 8 个新测试（LLM Client 6 + Web Handler 2）

## 三、架构优化

### 3.1 Chat 层窄接口

`internal/service/chat` 定义了 `LongTermMemoryProvider` 窄接口：

```go
type LongTermMemoryProvider interface {
    GetRecentForContext(ctx context.Context, userID int64, limit int) ([]string, error)
}
```

替代之前对完整 `memorysvc.MemoryService` 的依赖。好处：
- chat 层只依赖它真正需要的一个方法
- `MemoryService` 后续扩展（Delete/Update 等）不再影响聊天模块
- mock 测试更简洁

### 3.2 Graphify 生成物清理

- `.gitignore` 新增 `graphify-out/`
- 已跟踪的 graphify 文件从 git 索引移除
