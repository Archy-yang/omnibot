## 关键设计决策

1. **永久存储 + 滑动窗口**：所有消息永久落库，但调用 LLM 时只取最近 10 轮
2. **全局单会话**：同一用户共享一个上下文，不做多会话切换
3. **只文本入上下文**：图片、语音、视频等非文本消息正常回复但不进入上下文
4. **失败回复仍入上下文**：LLM 调用失败的兜底回复也保存，避免上下文断裂
5. **MsgID 唯一索引去重**：通过数据库唯一索引防止微信重试导致的重复消息

## 风险跟踪

| 风险 | 等级 | 应对措施 |
|------|------|----------|
| 上下文增加 Token 消耗 | 中 | MVP 固定 10 轮，后续根据成本数据调整 |
| 历史消息过长导致 LLM 超时 | 中 | V1.2.1 增加长度截断 |
| 旧上下文干扰新话题 | 高 | 密切观察埋点，必要时减少轮数或增加清除命令 |
| 数据库故障影响对话 | 高 | 已实现降级策略，DB 失败时退化为单轮模式 |
