## 一、为什么需要这份文档

v1.5 ~ v1.10 累积 6 个迭代,**每一次都用「TDD 红绿 + go build + go test 全绿」作为验证基线,真实运行验证次次跳过**:

| 迭代 | smoke 状态 | 实际验证 |
|------|-----------|----------|
| v1.5 Agent 基本能力 | ❌ 跳过 | LLM base_url 配置是 `http://localhost:9999/v1`(不存在的地址),Agent 工具调用未在真实 LLM 上跑过 |
| v1.6 飞书机器人 | ❌ 跳过 | 从未真实连过飞书自建应用 |
| v1.8 UserChannels 切换 | ❌ 跳过 | 微信端切到通道路径,从未真实跑过公众号回调 |
| v1.9 WeChat XML 解耦 | ❌ 跳过 | 同上 |
| v1.10 Web 设置面板 Tab 化 | ❌ 跳过 | 浏览器交互、Tab 切换、视觉密度均未验证 |

> 核心问题:`go test ./... 全绿 ≠ 这玩意能运行`。`verify` 技能的核心原则——「verification 是运行时观察」——在过去 6 个迭代里没被严格执行。

**结论**:master 上有 6 个迭代的代码没有跑过真实端到端 smoke。在进入 v2.0 发布之前,必须先把这笔账还清。

---

## 二、为什么不直接进 v2.0 发布

考虑过三条路:

| 路线 | 工时 | 价值 | 风险 |
|------|------|------|------|
| **A. 回头补 smoke** | 1~2 天 | 把 6 个迭代积累的不确定性一次性消掉 | 可能发现 production-blocker bug |
| B. 进 v2.0 发布(部署文档/生产配置/产品介绍) | 1~2 周 | 完整的对外交付物 | **不先做 A,B 就是花瓶**——文档写得再漂亮,真实跑不通毫无意义 |
| C. 启动 v2.x 跨入口绑定(账户体系) | 2~3 周 | 真正激活 v1.8 UserChannels 的产品价值 | **不先做 A,核心功能下面可能藏 bug**,且 user_id 合并涉及跨表外键迁移 |

**B 和 C 的共同前提都是 A 必须先做**。

---

## 三、决策:先 A,再 B

锁定执行顺序:

```
v1.11 端到端 smoke 收尾(本文档定义)
        ↓
   smoke 全过?
   ├─ 是 → 进 v2.0 发布(B 路线)
   └─ 否 → 列 P0/P1 bug 修复,然后才进 v2.0
        ↓
v2.0 正式发布
        ↓
v2.x 后续(跨入口绑定 / 监控告警 / 更多入口,见路线图 v3.0)
```

理由(强观点):

1. **前面欠的 smoke 不补,后面什么都是空中楼阁**。`go test 全绿 ≠ 产品能跑`,这是开发流程上应该一开始就盯紧但被忽视了 6 个迭代的事。
2. **A 是低成本高 ROI**:1~2 天投入,把 6 个迭代积累的不确定性一次性消掉。
3. **A 的结果决定 B/C 的优先级**:
   - 若 A 全过 → 心里底气足 → B(发布)和 C(新功能)都可推进
   - 若 A 发现关键 bug → 先修 → B/C 自动延后

## 五、v1.11 范围之外(明确不做)

- **新功能**:本次只验证已有能力,不开发新功能
- **性能压测**:留 v2.0 发布前最后一波,不在 smoke 范围
- **跨入口绑定流程**:留 v2.x
- **生产部署文档**:留 v2.0
- **真实微信公众号(正式号)**:测试号即可,正式号有备案要求且与 smoke 目标无关

## 六、smoke 不通过怎么办

按发现问题的严重程度分级:

| 级别 | 定义 | 处理 |
|------|------|------|
| **P0** | 主流程崩溃 / 数据错乱 / 安全漏洞 | 立即修,以 hotfix 形式独立提交,smoke 重跑 |
| **P1** | 非主流程错误 / 体验问题 / 边界 case 失败 | 列入 issue,在 v2.0 前修复 |
| **P2** | 视觉问题 / 文案不当 / 优化建议 | 列入 backlog,v2.0 之后处理 |

P0 修复同样要走 TDD + 真实 smoke 重跑——不能让 fix 又制造新的「未验证」债务。

---

## 七、决策原则记录

这条路线的产生过程本身值得记下来,作为后续迭代的参考:

1. **诚实优于进度**:愿意承认 6 个迭代的 smoke 债,比继续往前堆代码更重要
2. **快胜过深**:1~2 天的 smoke 收尾,比 1~2 周的「v2.0 部署文档」对 v2.0 实际价值更高
3. **强观点,但开放**:推荐了 A 路线,但 B/C 都列出了利弊
4. **范围控制是 OmniBot 的核心纪律**:不夹带其他工作,只做 smoke
