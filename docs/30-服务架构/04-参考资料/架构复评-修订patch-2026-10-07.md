# A 组 🔴 必改 —— `manual` 记忆静默截断

> 对应报告 **P0-1**。核心事实：`manual` 曾是**无预算全量注入**，M8.3 引入 2000 token 预算后变成**可被整条丢弃且无任何提示**；代码注释自称「不截断」与实现相反。
>
> **修复方案选型**（请二选一，本条按**方案甲**给替换文本）：
>
> - **方案甲（推荐）**：`manual` 恒全量常驻、不参与截断；预算只约束 `pinned auto`。理由：§6.5 的契约原文就是「手动记忆=常驻，每轮**全量**注入（**小而有界**）」，其"有界"由人工写入与 200 字/条天然保证；2000 预算本是 M8.3 为新增的 pinned 层引入的。此方案**恢复改造前的既有契约**，改动最小、语义最直白。
> - **方案乙**：保留"总量硬上限"，但把预算做成可配（`MessageServiceDeps.MemoryBlockMaxTokens`），并为**被丢弃的 manual** 单出一行提示。适用于你确实担心 manual 无限增长的场景；代价是注入端要多一套提示文案与测试。
>
> 下面 A2 给的是方案甲。

## A2 —— 修实现：`manual` 豁免预算

**目标位置**：`internal/service/chat/message_service.go:282-302`

**现状原文**：

```go
	// 预算内组装:manual 全量 → pinned auto 依次保留,超预算截断
	kept := make([]string, 0, len(inj.Manual)+len(inj.PinnedAuto))
	truncated := 0
	used := 0
	appendItem := func(item string) bool {
		cost := EstimateTokens(item) + 2 // 编号与换行开销
		if used+cost > s.memoryBlockMaxTokens {
			return false
		}
		used += cost
		kept = append(kept, item)
		return true
	}
	for _, m := range inj.Manual {
		appendItem(m) // manual 全量优先:超预算也不截断(继续尝试下一条)
	}
	for _, p := range inj.PinnedAuto {
		if !appendItem(p) {
			truncated++
		}
	}
```

**操作**：整体替换

**替换文本**：

```go
	// 组装(§6.5 契约 + M8.3 §14.2.4):manual = 用户意志,契约是「全量常驻」——不参与截断;
	// 预算只约束 M8.3 新增的 pinned auto 层(助手笔记,量可增长)。
	// manual 的成本仍计入起点,故「manual 全量 + pinned 预算」的总量依旧受 memoryBlockMaxTokens 约束。
	kept := make([]string, 0, len(inj.Manual)+len(inj.PinnedAuto))
	used := 0
	for _, m := range inj.Manual {
		kept = append(kept, m)        // 全量注入,不做预算判断(超预算也不丢)
		used += EstimateTokens(m) + 2 // 编号与换行开销
	}
	truncated := 0
	for _, p := range inj.PinnedAuto {
		cost := EstimateTokens(p) + 2
		if used+cost > s.memoryBlockMaxTokens {
			truncated++ // 只截断 pinned,并计入存在性提示
			continue
		}
		used += cost
		kept = append(kept, p)
	}
```

> **语义确认**：`message_service.go:316` 的 `remaining := inj.AutoCount - len(inj.PinnedAuto) + truncated` **无需改动**——`truncated` 的含义（被截断的 pinned auto 条数）保持不变。
>
> **可选增强**（不加也不错）：在 `truncated > 0` 时补一条 `logger.WarnWithFields("memory: 常驻置顶记忆超预算被截断", ...)`，让"用户置顶了却没进去"可观测。

## E2 —— loop 快照取样：两端各取（⚠️ 需先确认方案）

**目标位置**：`internal/repository/memory/memory_repo.go:189-198`（`ListOpenLoops`）

**现状原文**：

```go
// ListOpenLoops 未决 loop(M8 世界观快照用):最旧优先,最多 limit 条。
func (r *memoryRepository) ListOpenLoops(userID int64, limit int) ([]*memorydomain.Memory, error) {
	var memories []*memorydomain.Memory
	q := r.db.Where("user_id = ? AND kind = ? AND loop_status = ?", userID, memorydomain.MemoryKindLoop, memorydomain.MemoryLoopStatusOpen).
		Order("created_at ASC")
	if limit > 0 {
		q = q.Limit(limit)
	}
	err := q.Find(&memories).Error
	return memories, err
}
```

**问题**：`created_at ASC` + 上限 20 → **最新 loop 最难被看到**，而最新 loop 才是最可能刚被了结的。设计文档的原始理由是"窗口随关闭动作轮转覆盖，新 loop 不会永久挤掉旧 loop"——但这正好把风险转移给了新 loop，且 §14.2.2 承诺的"管理面手动关闭入口"并未实现（见 E3），逃生口不存在。

**操作**：**先确认方案再改**。三个候选：

| 方案 | 做法 | 代价 |
|------|------|------|
| 甲（推荐） | 两端各取 `limit/2`（ASC 取最旧一半 + DESC 取最新一半，按 ID 去重合并） | 一次额外查询；覆盖两个极端，中间段仍可能不可见 |
| 乙 | 改为 `ORDER BY updated_at DESC`（新近提及/变更优先） | 旧 loop 可能永久不被看见 |
| 丙 | 保持 ASC，但**先把 E3 的关闭入口做出来**作为逃生口 | 不解决"新 loop 看不见"，但风险有兜底 |

> 我的判断：**甲 + 丙 一起做**才闭环（甲保证可见性，丙保证兜底）。**单独做乙不建议**。

**替换文本**（方案甲，供参考；实现前请确认）：

```go
// ListOpenLoops 未决 loop(M8 世界观快照用):两端各取一半,最多 limit 条。
// 只取最旧会让最新 loop(最可能刚被了结的)永远进不了快照,反之亦然——故两端覆盖。
// 返回顺序:created_at ASC(稳定,便于 prompt 内编号引用)。
func (r *memoryRepository) ListOpenLoops(userID int64, limit int) ([]*memorydomain.Memory, error) {
	if limit <= 0 {
		limit = snapshotDefaultLoopLimit
	}
	half := limit/2 + limit%2
	base := func() *gorm.DB {
		return r.db.Where("user_id = ? AND kind = ? AND loop_status = ?",
			userID, memorydomain.MemoryKindLoop, memorydomain.MemoryLoopStatusOpen)
	}
	var oldest, newest []*memorydomain.Memory
	if err := base().Order("created_at ASC").Limit(half).Find(&oldest).Error; err != nil {
		return nil, err
	}
	if err := base().Order("created_at DESC").Limit(limit - half).Find(&newest).Error; err != nil {
		return nil, err
	}
	seen := make(map[int64]struct{}, limit)
	merged := make([]*memorydomain.Memory, 0, limit)
	for _, list := range [][]*memorydomain.Memory{oldest, newest} {
		for _, m := range list {
			if _, dup := seen[m.ID]; dup {
				continue
			}
			seen[m.ID] = struct{}{}
			merged = append(merged, m)
		}
	}
	sort.Slice(merged, func(i, j int) bool { return merged[i].CreatedAt.Before(merged[j].CreatedAt) })
	return merged, nil
}
```

> **两个实现细节**：
> ①需补 `sort` import（该文件当前 import 为 `time` / `memorydomain` / `gorm` / `gorm/clause`）；
> ②上面的 `snapshotDefaultLoopLimit` **不存在**——既有的 `snapshotMaxLoops = 20` 定义在
> `internal/service/memory/digest_reconcile.go`（service 层），**repository 不能反向依赖**。
> 请直接在 repository 内定义本地常量（如 `const defaultOpenLoopLimit = 20`），或由调用方
> 始终传入 limit（现有唯一调用点 `buildWorldViewSnapshot` 已传 `snapshotMaxLoops`，故内联兜底即可）。
