## H3 —— 前端死类型 `SetLoopStatusRequest`

**问题**：`frontend/src/types/api.ts:229` 导出了 `SetLoopStatusRequest`，但无人引用（`services/memory.ts` 用了内联 `'open' | 'closed'`）。前端宪章要求 TypeScript 全程类型化，留着"声明了却不用的类型"会诱导后来者以为它是契约的一部分。

**目标位置**：`frontend/src/types/api.ts`

**现状原文**：

```ts
/**
 * loop 状态迁移请求类型(E3:管理面关闭/重开)
 */
export interface SetLoopStatusRequest {
  status: 'open' | 'closed';
}
```

**操作**：二选一。

- **方案甲（推荐，删死代码）**：删除上述整块。
- **方案乙（让它成为真契约）**：保留类型，并把 `services/memory.ts` 的签名改为使用它：

  **现状原文**（`frontend/src/services/memory.ts`）：
  ```ts
  async setLoopStatus(id: number, status: 'open' | 'closed'): Promise<SetLoopStatusResponse> {
  ```
  **替换文本**：
  ```ts
  async setLoopStatus(id: number, requestBody: SetLoopStatusRequest): Promise<SetLoopStatusResponse> {
  ```
  同时把调用处 `setLoopStatus(id, status)` 改为 `setLoopStatus(id, { status })`（在 `stores/memory.ts`）。

> 方案乙更"重"（动三处），方案甲一行了事，且该类型并无复用价值——推荐甲。

## H4 —— 构建保险：`vue-tsc` 增量缓存 + gofmt 门禁

**背景（诚实标注）**：审查期间我**一度**观察到 `frontend/src/services/memory.ts` 报 `TS1005: ',' expected`
（`pinMemory` 与 `setLoopStatus` 之间缺逗号），而同一时段的 `vue-tsc -b` 返回 exit 0。该文件随后被修正
（blob `d6ad540` → `6d4b437`）并随 `4e7b6b8` 固化，**最终状态干净**（TS 编译器 API `parseDiagnostics: 0`、
`vue-tsc -b --force` exit 0、`npm run build` 成功）。

我尝试用最小工程复现"`vue-tsc -b` 被过期 `node_modules/.tmp/*.tsbuildinfo` 短路"，但**探针无效**
（三次都返回 0，含 `--force`），**无法定论**。因此这**不算缺陷**，只作为一条低成本保险建议。

**操作**：二选一或都做。

**① 前端构建绕过增量缓存**（`frontend/package.json:8`）

- **现状原文**：
  ```json
  "build": "vue-tsc -b && vite build",
  ```
- **替换文本**：
  ```json
  "build": "vue-tsc -b --force && vite build",
  ```
- 代价：每次全量类型检查。本项目 154 模块量级、构建约 1.2s，**成本可忽略**。

**② `Makefile` 加 gofmt 门禁**（仓库确无 CI，我核实过 `.github/workflows` / `.gitlab-ci.yml` / `.circleci` 均不存在，故只能靠 Makefile）

在 `test-backend` 附近追加：

```make
fmt-check:  ## 检查最近一次提交涉及的 Go 文件是否 gofmt 合规
	@files=$$(git show --name-only --pretty=format: HEAD -- '*.go' | grep -v '^$$' || true); \
	if [ -n "$$files" ]; then \
	  bad=$$(echo "$$files" | xargs gofmt -l 2>/dev/null); \
	  if [ -n "$$bad" ]; then echo "以下文件未格式化:"; echo "$$bad"; exit 1; fi; \
	fi
	@echo "gofmt OK"
```

并把它挂进 `test-all`：`test-all: fmt-check test-backend`。

> 只查"最近一次提交涉及的文件"而非全仓——全仓尚有 14 个历史遗留违规（`internal/db/database.go`、`domain/agent/*`、
> `service/agent/service.go` 等），一次性全改会淹没 diff。
