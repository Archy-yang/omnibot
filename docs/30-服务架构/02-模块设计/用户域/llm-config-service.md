## 1. 这个服务解决什么问题？

**核心问题**：
1. 每个用户想用自己的 LLM API Key，不要用系统的配额
2. 不同用户可以用不同的模型提供商（OpenAI、Anthropic、国内模型等）
3. API Key 是敏感数据，不能明文存储

**解决方案**：
独立的 LLM 配置服务，每个用户独立配置，AES-256-GCM 加密存储。

读之前你需要知道：
- [用户核心服务](./user-service.md)
- [AES 加密模块](../通用能力/crypto.md)

## 2. 核心领域模型

### LLMConfig 实体

| 字段 | 类型 | 说明 |
|------|------|------|
| ID | int64 | 主键 |
| UserID | int64 | 关联的用户 ID，唯一索引 |
| APIKey | string | 加密后的 API Key |
| BaseURL | string | 自定义 API 端点（可空） |
| Model | string | 模型名称（可空） |
| Status | int | 配置状态：0=禁用，1=启用 |
| CreatedAt | time.Time | 创建时间 |
| UpdatedAt | time.Time | 更新时间 |

**唯一约束**：每个用户只能有一份自定义配置（UserID 唯一索引）。

## 3. 服务接口

### 设置 API Key

```go
SetAPIKey(userID int64, apiKey string) error
```

**行为**：
1. 校验 API Key 格式（必须以 `sk-` 开头）
2. 校验长度（30-200 字符）
3. AES-256-GCM 加密
4. 写入数据库（不存在则创建，存在则更新）

### 设置自定义 BaseURL

```go
SetBaseURL(userID int64, baseURL string) error
```

**行为**：
1. 校验 URL 格式（必须以 http:// 或 https:// 开头）
2. 无需加密，明文存储
3. 空字符串表示清除自定义地址，回退到系统默认

### 设置默认模型

```go
SetModel(userID int64, model string) error
```

**行为**：
1. 仅校验非空，不校验模型是否真实存在
2. 交给 LLM 客户端层去处理模型不支持的情况

### 获取配置（内部使用）

```go
GetConfigForUser(userID int64) (
    apiKey string,
    baseURL string,
    model string,
    hasCustom bool,
    err error,
)
```

**行为**：
1. 查询用户配置
2. 自动解密 API Key
3. 如果用户没有自定义配置，返回 `hasCustom = false`
4. **注意**：这个接口返回明文 Key，仅限内部服务调用，绝对不能暴露给外部

### 获取配置视图（展示用）

```go
GetConfigView(userID int64) (*LLMConfigView, error)
```

返回脱敏后的配置视图，用于展示给用户：

```go
type LLMConfigView struct {
    APIKeyMasked  string  // 脱敏后的 Key，如 "sk-***xyz"
    BaseURL       string  // 明文展示
    Model         string  // 明文展示
    HasCustom     bool    // 是否有自定义配置
}
```

### 清除配置

```go
ClearConfig(userID int64) error
```

**行为**：
1. 物理删除用户配置记录
2. 用户回退到使用系统默认模型

## 4. 加密策略

### 加密算法

- **算法**：AES-256-GCM
- **密钥长度**：256 位（32 字节）
- **认证加密**：包含消息认证码（MAC），防篡改
- **随机 Nonce**：每次加密都用新的随机 Nonce，相同明文加密结果不同

### 密钥管理

- 加密密钥通过环境变量 `LLM_CONFIG_ENCRYPT_KEY` 配置
- 开发环境内置默认密钥（仅用于开发，严禁生产环境使用）
- 密钥轮换方案：v1.4+ 实现（双密钥兼容，老数据可以用老密钥解密，新数据用新密钥）

### 脱敏规则

展示时只显示前后各 3 个字符，中间用 `***` 代替：

| 原始 Key | 脱敏后 |
|----------|--------|
| `sk-abcdefghijklmnopqrstuvwxyz123456` | `sk-***456` |

## 5. LLM 调用时的配置优先级

```
用户发送消息
    ↓
检查是否有自定义配置？
    ├─ 有 → 使用用户的 API Key + BaseURL + Model 调用
    │       配额完全独立，不消耗系统配额
    │
    └─ 无 → 使用系统全局配置
```

### 错误降级

用户自定义配置调用失败时：
1. 记录错误日志
2. 回复友好提示：「您的自定义配置调用失败，请检查 API Key 是否正确」
3. **不会自动降级到系统配置**（避免用户以为在用自己的 Key 其实在用系统的）

## 6. 设计决策记录

### 决策1：为什么每个用户只能有一份配置？
- **背景**：要不要支持一个用户保存多套配置（工作用、个人用、测试用等）
- **决策**：v1.x 只支持一份配置
- **原因**：
  - 80% 的用户只需要一套配置
  - 多套配置需要 UI 支持切换，微信纯文本交互太麻烦
  - 未来可以加，先做最小可用

### 决策2：为什么加密用 AES-256-GCM，不是别的？
- **背景**：加密算法选择很多，AES、RSA、ChaCha20...
- **决策**：AES-256-GCM
- **原因**：
  - 标准算法，审计容易过
  - 硬件加速，性能好
  - 带认证加密（AEAD），可以防篡改
  - Go 标准库原生支持，不需要第三方依赖

### 决策3：为什么配置失败不自动降级到系统配置？
- **背景**：用户 Key 过期了，要不要自动用系统的，让用户「无感」？
- **决策**：不自动降级，明确报错
- **原因**：
  - 很多用户设置自定义 Key 就是为了用自己的配额，不想用系统的
  - 自动降级会导致用户以为自己的 Key 还在生效，产生误解
  - 明确报错，用户可以立刻知道有问题，及时修复

### 决策4：为什么 URL 和 Model 不加密？
- **背景**：加密是不是应该越全面越好？
- **决策**：只加密最敏感的 API Key，其他不加密
- **原因**：
  - 安全与便利的平衡
  - URL 和 Model 本身不是敏感数据，泄露了也不会造成损失
  - 加密会增加运维成本（调试、迁移都麻烦）
  - 最小安全原则：只加密必须加密的

## 7. 常见问题

### Q: 用户把自己的 Key 泄露了怎么办？
**A**: 这是用户自己的责任，我们只负责存储安全。建议在帮助文档里提醒用户：
1. 不要把 API Key 发给任何人
2. 定期轮换 API Key
3. 给 API Key 设置合理的额度限制

### Q: 可以支持非 OpenAI 格式的模型吗？
**A**: v1.x 只支持 OpenAI 兼容格式（因为这是行业事实标准，几乎所有新模型都兼容）。未来可以扩展配置的 Provider 字段，支持更多格式。

### Q: 可以看到用户的明文 API Key 吗？
**A**: 技术上可以（服务器启动时加载了密钥，运行时可以解密），但流程上禁止，只有在用户主动授权的排查场景下才能临时查看，并且必须记录审计日志。
