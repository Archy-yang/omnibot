# 个人管家演进路线图

> 2026-10-14 立项。核心目标：让 OmniBot 从"具备长期记忆和执行能力的 Agent"演进为
> "能够陪伴、记录、理解和处理个人事务的长期私人管家"。
> **不重构现有 Agent Framework**，重点是补齐长期相处所需的产品能力。
> 规划来源：外部建议（ChatGPT，2026-10-14）评审后映射到现有底座形成。

## 1. 现状底座盘点（规划的前提）

规划基于以下**已落地**能力（详见 16 号路线图与各技术方案落地记录）：

| 底座 | 已有能力 | 对本规划的意义 |
|------|----------|----------------|
| 记忆收敛（M6） | Matter 主题档案、Fact 切分、Episode/Digest 归集、Loop 生命周期、pinned 常驻 core、Turn/水位锚定沉淀 | Topic Archive 的数据层已存在 |
| 中期记忆（M7） | 消息级向量、三段式检索 | Recall 的时间/主题维度是在其上加过滤，不是新检索 |
| Conversation Recall | 历史对话召回、Compact/Recall | Personal Recall 的骨架 |
| Task Runtime + 后台 Agent | 派活/汇报/CAS/Control Signal | Persistent Tasks 的执行底座 |
| Skill / MCP / Sandbox | DB 技能库、连接器、一次性容器脚本执行 | Document Integration 与自动化任务的工具面 |
| feishu_tool | 多用户授权（19 号）、文档/表格/消息全业务域 | 个人文档同步的通道 |
| 订阅源 | 定时抓取与推送 | Proactive Butler / 周期任务的触发雏形 |

## 2. 阶段总览

| 阶段 | 主题 | 内容 | 性质 |
|------|------|------|------|
| 一 | **让管家学会记录** | Personal Journal、Topic Archive、Personal Recall | 记忆系统产品化 + 时间维度增强 |
| 二 | **让管家越来越了解你** | Document Integration、Style Evolution、Context Evolution | 文档编排 + 慢演化机制 |
| 三 | **让管家主动替你操心** | Persistent Tasks、Proactive Butler | 调度底座 + 主动性 |
| 四 | **让管家持续推进目标** | Personal Goals、自主任务建议 | 目标闭环 |

每阶段结束回头看一次本路线图，按真实使用反馈调整后续优先级。

## 3. 第一阶段：让管家学会记录（下一轮重点）

> 验证目标：能从自然对话中持续积累**准确、有来源**的个人经历。

| 功能 | 表述（规划基线） | 实质 | 对应方案 |
|------|------------------|------|----------|
| Personal Journal | 用户正常聊天，Agent 自动提取重要事件，按时间记录 | 现有沉淀管线（Fact/Episode/Digest）的**时间轴用户视图**：可浏览、可纠正、可禁止沉淀 | 21 号 |
| Topic Archive | 同一主题的多次讨论归集为持续更新的档案，记录关键决策与状态变化 | Matter 的**档案视图**：展示 Matter 的演进时间线、关联 episode、决策脉络 | 21 号（与 Journal 同批评审数据层，方案可拆） |
| Personal Recall | 自然语言准确回忆某段经历/决定/工作，给出时间线与原始对话依据 | 现有三段式检索**加时间/主题/事件维度**过滤与呈现 | 22 号 |

第一阶段预期 1-2 个迭代可见成果（底座已在，主要是产品化）。

## 4. 第二阶段：让管家越来越了解你

| 功能 | 说明 | 关键约束 |
|------|------|----------|
| Document Integration | 用 feishu_tool 将 Journal/Archive 同步为飞书文档（旅行日记、工作日志、项目记录），自动创建 + 增量更新 + 事后修正 | 幂等同步（防重复建文档）；用户确认文档归属位置 |
| Style Evolution | 语气/表达结构/交流习惯缓慢演化 | **只积累证据，不自动演化**（首轮）；evidence-gated 慢更新 + 可回滚，禁止自我强化 |
| Context Evolution | 识别用户偏好、决策及其变化、过期认知 | 与 Style 同批设计；画像注入 prompt 必须走确认机制（吸取 prompt 失准教训） |

## 5. 第三阶段：让管家主动替你操心

| 功能 | 说明 | 关键约束 |
|------|------|----------|
| Persistent Tasks | Task Runtime 上增加调度、恢复、周期执行（"每周关注""明天提醒""持续跟踪"） | 复用订阅源触发雏形；任务状态可恢复 |
| Proactive Butler | 基于近期经历适时关心/建议，非机械提醒 | 授权范围内；频率克制；可一键关闭 |

## 6. 第四阶段：让管家持续推进目标（中期，暂不细化）

Personal Goals：长期目标与事项/任务/日志关联，形成记录→行动→反馈→调整闭环。
到第三阶段结束时再细化——目标管理依赖前三个阶段的数据与机制成熟。

## 7. 贯穿所有阶段的基础要求

不做成独立功能，但从第一行代码开始保证：

1. **信息可溯源、可纠正**：自动生成的日志/记忆/判断可追溯原始对话（episode/digest 本带 Turn 来源，UI 必须透出）；用户可纠正错误、可禁止某些内容长期沉淀。
2. **演化稳定、可控制**：风格与认知基于长期证据缓慢更新，不能自我强化或突变；任何画像变更可回滚。
3. **持续验证质量**：建立真实对话回放与评估用例，检查记录准确性、历史召回成功率、风格稳定性；同时修复已知 Review 问题（并发、资源限制、状态一致性）。

## 8. 边界与不做

- 不重构 Agent Framework；不为规划中的功能预建抽象。
- Proactive Butler 不做未经授权的打扰式推送；第一阶段一切被动。
- 用户画像/沟通风格不自动注入 system prompt，必须显式确认机制。
- 单一长期对话模型不动摇：不为 Journal/Archive 引入会话概念，它们是长期对话之上的视图。

## 9. 工作方式

每个功能：**出技术方案（21 号顺延）→ 用户确认 → TDD 实施 → 文档同步**。
本路线图只定方向与优先级，不锁定实现；各方案落地后在本文件对应条目标注状态。
