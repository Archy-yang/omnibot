## 1. 这个文档解决什么问题？

给 Agent 一个**安全执行 Python/Shell 脚本**的通道：数据处理、格式转换、逻辑验证类任务不再需要"我口头教你算"或依赖硬编码工具；同时为 Skill 系统（指令包 + 可选脚本）提供执行底座。

核心矛盾：LLM 生成的代码不可信，而用户数据（记忆、配置、密钥）都在同一台宿主机上。本方案 = **一次性容器沙箱** + **四重资源限额** + **默认断网**，让"能跑代码"与"碰不到宿主"同时成立。

### 1.1 边界（首期明确不做）

| 不做 | 理由 |
|------|------|
| 产物文件投递 | 已拍板 MVP 只回 stdout/stderr；投递链路（存储+各渠道下载/发送）是独立项目 |
| 常驻热池 | 单用户低频执行，冷启动 0.5~2s 可接受；一次性容器的干净状态对 LLM 代码价值更大 |
| 网络白名单 UI | Spec 留 `Network` 字段，首期恒 false；将来 Skill 按声明放行时再开界面 |
| 用户自定义持久化脚本工具 | 13 号方案 §8 该边界**不解除**——那是"用户定义工具"（持久、可复用），本方案是"Agent 临时生成脚本"（一次性、随任务消亡），两回事 |

## 3. 总体设计

### 3.1 架构位置与分层

```
internal/domain/sandbox/       SandboxExecutor 接口 + Spec/Result DTO（纯 Go,零依赖）
internal/service/sandbox/      DockerExecutor 实现（docker SDK 依赖只进这个包）
internal/service/agent/tools/sandbox_run.go   builtin 工具,调 Executor
```

- 上游只依赖 `SandboxExecutor` 接口，不感知背后是 Docker——将来 Apple Containerization（macOS 26+）或远端 gVisor 加固均可新增实现，零改动上游
- 装配：`wire.go` 读 config 构造 `DockerExecutor`，注入工具工厂
- 无新表：沙箱无状态；工具定义走现有 `tools` 表 seed 机制

### 3.2 接口（抽象层不含任何容器概念）

```go
package sandbox

type File struct {
    Name    string // 相对 /workspace 的路径,禁止 ".."
    Content string
}

type SandboxSpec struct {
    Cmd      []string      // argv 直传不经 shell(防注入)
    Stdin    string        // 多行内容走 stdin(feishu_tool 先例)
    Files    []File        // 输入文件(脚本/数据)
    Env      []string      // K=V,仅显式声明项;不透传宿主环境
    Timeout  time.Duration // 服务端按 config 上限 clamp
    MemoryMB int64
    CPUCores float64
    Network  bool          // 首期恒 false
}

type SandboxResult struct {
    ExitCode int
    Stdout   string // 截断至 max_output_bytes
    Stderr   string // 同上
    Duration time.Duration
}

type SandboxExecutor interface {
    Run(ctx context.Context, spec SandboxSpec) (SandboxResult, error)
}
```

**镜像归属实现层**（设计评审修正）：镜像名是容器实现的部署决策，不是沙箱抽象的概念——DockerExecutor 构造时从 config 取 `Image`，Spec 与接口中不出现 image 字段。调用方也不声明"我要 python3"——镜像内容是部署者运维决策（预装了什么库），Agent 只管执行。

### 3.3 DockerExecutor 执行流程

1. 建 host 临时 scratch 目录，写入 `Files`（校验 Name：禁 `..`、禁绝对路径）
2. CreateContainer，HostConfig 硬编码安全项：
   - `NetworkMode: "none"`（Spec.Network 恒 false 的实现侧兜底）
   - `ReadonlyRootfs: true`
   - `Resources{Memory, NanoCPUs, PidsLimit}` 四重限额之三
   - scratch 挂载 `/workspace`（唯一 host 挂载点，读写）
   - 非 root 用户（镜像内建 `app` 用户）
3. Start + Attach 流式收集 stdout/stderr，超 `max_output_bytes` 截断
4. ctx 超时 → Stop（先 SIGTSTP 优雅期再 kill）；Wait 取 ExitCode
5. defer：Remove 容器 + 删 scratch 目录（幂等，失败仅 Warn 不影响返回）

**选型：官方 docker Go SDK**（`github.com/docker/docker`）而非 shell 出去调 CLI——错误结构化、超时/取消随 ctx 原生传递、流式读输出可控截断、两端（Docker Desktop / Linux daemon）行为一致。依赖较重但只进 `service/sandbox` 一个包；docker client 以窄接口注入（`DockerAPIClient`），单测 mock。

**可用性口径**：Docker 未运行时**不隐藏工具**，执行时返回引导文案（"沙箱不可用：Docker 未启动，请启动 Docker 后重试"）——沿用 feishu_tool 先例，用户启动后自愈免重启。工具清单 `Available` 恒 true（定义与 schema 无缺陷）。

## 4. 工具暴露

| 项 | 值 |
|----|----|
| 工具名 | `sandbox_run` |
| 注册方式 | `RegisterBuiltinSubOnly`（**子 Agent 专属**，对齐方向 B"管家不亲自干活"：主 Agent delegate 派活，子 Agent 跑脚本，同 rss_reader/web_read） |
| Capabilities | `code,script` |
| 参数 schema | `{cmd: string[], files?: [{name, content}], stdin?: string, timeout_seconds?: int}` |
| timeout 语义 | 缺省用 config 默认；传值按 config 上限 clamp（不报错，静默收敛） |
| 前端 | **零改动**——SettingsDrawer 工具清单自动出现（徽标"内置"，开关走现有 `/api/v1/tools`） |

工具描述要点（写给 LLM）：适合数据处理/转换/计算验证/批量文本加工；结果以 stdout 文本回传（有截断上限，大结果自行分段输出）；**无法联网**，需要联网信息先经 web_read 获取后以文件传入；不要把敏感信息写进脚本。

## 5. 镜像与配置

### 5.1 沙箱镜像

`docker/sandbox.Dockerfile`（repo 内，随代码演进）：

```dockerfile
FROM python:3.12-slim        # 自带 python3 + pip + bash
RUN pip install --no-cache-dir numpy pandas requests openpyxl \
 && useradd -m -u 1000 app
USER app
WORKDIR /workspace
```

构建：`make sandbox-image`（`docker build -t omnibot-sandbox:latest -f docker/sandbox.Dockerfile .`）。镜像属运维决策——预装库按需改 Dockerfile 重建，不进运行时参数。

### 5.2 配置（config.yaml，example 同步）

```yaml
sandbox:
  image: omnibot-sandbox:latest
  timeout_seconds: 60        # 单次执行上限(默认与 clamp 上限同值)
  memory_mb: 512
  cpu_cores: 1.0
  max_output_bytes: 32768
  pids_limit: 64
```

## 6. 安全收口

| 面 | 措施 |
|----|------|
| 网络 | 默认断网（`--network none`），外传通道封死 |
| 文件系统 | rootfs 只读；唯一可写 = 一次性 scratch（任务结束即删）；宿主其余路径不可见 |
| 权限 | 非 root 用户（uid 1000） |
| 资源 | 内存/CPU/PID/墙钟时间四重限额，失控脚本自然终止 |
| 注入 | argv 数组直传不经 shell；输入文件不与宿主文件混放 |
| 环境变量 | 不透传宿主 env，只用 Spec 显式声明项——密钥不进沙箱 |
| 日志 | 只记元数据（时长/退出码/输出字节数），**不记脚本内容与输出全文**（安全红线） |

**已知限制**（记录在案，非阻塞）：容器级隔离与宿主共享内核，理论上存在内核漏洞逃逸面。单用户自部署场景接受；远程服务器部署可用 gVisor（runsc）runtime 加固——换 Docker runtime 参数，代码零改动（`sandbox.runtime: runsc` 预留配置位）。
