## 1. 核心思路

绑定关系 = 一行 `user_channels(channel_type="feishu", channel_user_id=open_id, user_id=web账号)`。
v2.1 已为 `(channel_type, channel_user_id)` 建复合唯一索引 → 天然防「一个飞书号绑多账号」。
本期新增的是「绑定码」这个临时凭证,以及飞书入口从「自动建号」改为「查已绑定 / 引导」。

## 2. 绑定码存储 —— DB 表方案

绑定码持久化到 DB 表 `feishu_bind_codes`,重启不丢、支持后续多实例。

### 2.1 domain 实体

`internal/domain/user/feishu_bind_code.go`:
```go
type FeishuBindCode struct {
    ID        int64     `gorm:"primaryKey;autoIncrement"`
    UserID    int64     `gorm:"not null;uniqueIndex"` // 一账号同时只有一个有效码,重新生成覆盖
    Code      string    `gorm:"size:6;not null;index"` // 6 位数字
    ExpiresAt time.Time `gorm:"not null"`
    CreatedAt time.Time `gorm:"not null"`
    UpdatedAt time.Time `gorm:"not null"`
}
func (FeishuBindCode) TableName() string { return "feishu_bind_codes" }
func (c *FeishuBindCode) IsExpired(now time.Time) bool { return now.After(c.ExpiresAt) }
```
- `user_id` 唯一索引:一个账号同时只有一个有效码。重新生成 = upsert(覆盖旧行)→ 旧码自然作废
- `code` 建普通索引:飞书端按 code 查
- AutoMigrate 挂到 database.go

### 2.2 Repository

`internal/repository/user/feishu_bind_code_repo.go`:
```go
type FeishuBindCodeRepository interface {
    Upsert(code *user.FeishuBindCode) error       // 按 user_id 覆盖(重新生成作废旧码)
    GetByCode(code string) (*user.FeishuBindCode, error)
    GetByUserID(userID int64) (*user.FeishuBindCode, error)
    DeleteByUserID(userID int64) error            // 绑定成功后删码
}
```
- `Upsert`:`clause.OnConflict{Columns:{user_id}, UpdateAll:true}` —— 同账号重新生成直接覆盖,旧码失效
- 6 位码用 `crypto/rand` 生成 `000000~999999`(service 层)
- 过期不单独起清理 goroutine:`GetByCode` 后由 service 判 `IsExpired`,过期视为无效
  (个人项目,过期行留库无害;若在意可后续加定时清理)

## 3. Service 层 —— BindingService

`internal/service/user/binding_service.go`:
```go
type BindingService struct {
    channelRepo  UserChannelRepository       // 复用现有(GetByChannel/Create/GetByUserID)
    bindCodeRepo FeishuBindCodeRepository     // 新增
    codeTTL      time.Duration                // 5 分钟(PRD 4.1)
}

// web 端:生成绑定码(upsert,旧码作废)
func (s *BindingService) GenerateCode(userID int64) (code string, expiresAt time.Time, err error)
//   账号已绑飞书 → ErrAccountAlreadyBound

// web 端:查绑定状态
func (s *BindingService) IsFeishuBound(userID int64) (bool, error)

// 飞书端:提交绑定码
func (s *BindingService) BindFeishu(code, openID string) error
//   码不存在/过期 → ErrCodeInvalid
//   该 open_id 已绑其他账号 → ErrFeishuAlreadyBound
//   码对应账号已绑飞书 → ErrAccountAlreadyBound
//   成功 → 建 UserChannel + 删码

// 飞书端:解析已绑定身份
func (s *BindingService) ResolveFeishuUserID(openID string) (userID int64, bound bool, err error)
```

**Sentinel errors**(service/user 包级):
- `ErrCodeInvalid`
- `ErrFeishuAlreadyBound`
- `ErrAccountAlreadyBound`

**GenerateCode**:先查账号是否已绑飞书(已绑 → ErrAccountAlreadyBound);
crypto/rand 生成 6 位码;`bindCodeRepo.Upsert`(按 user_id 覆盖,旧码失效)。

**BindFeishu 校验顺序**(全部在校验后才写库):
1. `bindCodeRepo.GetByCode(code)`:不存在 → ErrCodeInvalid;`IsExpired` → ErrCodeInvalid
2. `channelRepo.GetByChannel("feishu", openID)` 存在 → ErrFeishuAlreadyBound
3. 码对应账号已绑飞书(遍历 `GetByUserID` 找 feishu 类型)→ ErrAccountAlreadyBound
4. `channelRepo.Create(NewUserChannel(code.UserID, "feishu", openID))`
   - 唯一索引冲突兜底并发 → ErrFeishuAlreadyBound
5. 成功后 `bindCodeRepo.DeleteByUserID(code.UserID)`(删码,幂等)

**幂等**(PRD 7.3):同一码重复提交,第 1 次成功后码已删 → 第 2 次 GetByCode 返回 not found → ErrCodeInvalid。
步骤 2 也会拦(open_id 已绑)。

## 4. 飞书 handler 改造

`internal/channel/feishu/handler.go` HandleInbound 重写身份解析段:

移除对 `UserService.GetOrCreateByChannel` 的依赖,改依赖新的 `BindingService` 接口
(feishu 包内定义):
```go
type BindingService interface {
    BindFeishu(code, openID string) error
    ResolveFeishuUserID(openID string) (int64, bool, error)
}
```

新 pipeline:
```
p2p + 非空(现有)
  ↓
解析 "绑定 <6位数字>"(正则 ^绑定 (\d{6})$,先 TrimSpace)
  ├─ 命中 → BindFeishu(code, openID) → 按结果回复(见下表)→ return
  └─ 未命中 ↓
ResolveFeishuUserID(openID)
  ├─ bound=true  → userID 走原 Agent pipeline(SaveUserMessage→BuildContext→Run→回复)
  └─ bound=false → 回复绑定引导(见 5.4 文案),不建号、不进对话 → return
```

**绑定结果回复**(PRD 5.2,errors.Is 映射):
| error | 飞书回复 |
|---|---|
| nil | `绑定成功!现在可以在飞书跟我聊了` |
| ErrCodeInvalid | `绑定码无效或已过期,请在 web 端重新获取` |
| ErrFeishuAlreadyBound | `该飞书号已绑定其他账号` |
| ErrAccountAlreadyBound | `你的账号已绑定飞书,如需更换请稍后(暂不支持)` |

**未绑定引导**(PRD 5.4,多行):
```
你还没有绑定 OmniBot 账号。请先在 web 端登录,在设置里获取绑定码,
然后在这里发送「绑定 + 空格 + 绑定码」(例如 绑定 123456)完成绑定。
```
绑定相关回复走 `SendText`(纯文本足够,无需卡片)。

## 5. Web API

`internal/api/web/feishu_bind_handler.go`(新文件):
```go
type BindingService interface {
    GenerateCode(userID int64) (string, time.Time, error)
    IsFeishuBound(userID int64) (bool, error)
}
type FeishuBindHandler struct { svc BindingService }

// GET /api/v1/user/feishu/binding → {bound: bool}
func (h) HandleGetBindingStatus(c)

// POST /api/v1/user/feishu/bind-code → {code, expires_at} 或 409
func (h) HandleGenerateBindCode(c)
//   ErrAccountAlreadyBound → 409 {"error":"你的账号已绑定飞书"}
```
两个接口都挂在已鉴权的 `/api/v1/user` 组下(v2.1 已挂 AuthRequired),
handler 用 `c.GetInt64(middleware.AuthUserIDKey)` 取当前用户。

## 6. 装配(routes.go)

- `bindCodeRepo := userRepo.NewFeishuBindCodeRepository(dbConn.GetGormDB())`
- `bindingSvc := userService.NewBindingService(userChannelRepository, bindCodeRepo, 5*time.Minute)`
- web:`feishuBindHandler := web.NewFeishuBindHandler(bindingSvc)`,挂 2 个路由到 userAPIGroup
- 飞书:`startFeishuChannel` 增加 `bindingSvc` 参数,传给 `NewMessageHandler`
- 绑定码走 DB,web 与 feishu 各自持有 bindingSvc 也无妨(数据在库里),
  但仍建议传同一实例(省一次构造,codeTTL 一致)

## 7. 前端

`SettingsDrawer.vue` 新增「飞书绑定」区块(关于 section 上方或独立):
- 打开抽屉时 `GET /user/feishu/binding` → bound?
  - bound=true:显示「已绑定飞书」
  - bound=false:显示「获取绑定码」按钮
- 点按钮 → `POST /user/feishu/bind-code` → 显示 6 位码 + 5 分钟倒计时 + 操作说明
  「在飞书向机器人发送:绑定 <码>」
- 「重新获取」按钮:再次 POST(旧码后端自动作废)
- 倒计时归零:码置灰,提示重新获取

`services/config.ts` 加 `getFeishuBinding()` / `generateFeishuBindCode()`。
`types/api.ts` 加对应响应类型。

   (Upsert 覆盖/GetByCode/GetByUserID/DeleteByUserID/user_id 唯一)+ AutoMigrate

## 9. 不做(PRD 3.2)

## 10. 安全对齐

- 绑定码 crypto/rand 生成,5 分钟过期,一码一账号(PRD 7.1)
- 错误提示不含其他账号信息(不说"绑定的是谁")(PRD 7.1)
- open_id 不入日志明文以外的持久化(现有约定不变)
- 复用 v2.1 唯一索引兜底并发(PRD 7.3)
