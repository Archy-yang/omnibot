# 组件设计规范

## 概述

本文档定义 OmniBot 前端组件设计规范，包括组件划分原则、组件 API 设计、组件文档规范等。

---

## 组件划分原则

### 1. 按复用层级划分

| 层级 | 命名前缀 | 说明 | 示例 |
|------|----------|------|------|
| 基础组件 | `Base` | 通用 UI 原子组件，与业务无关 | `BaseButton`, `BaseInput` |
| 业务组件 | 模块名开头 | 特定业务场景下的可复用组件 | `ChatMessage`, `ChatInput` |
| 页面组件 | 页面名开头 | 完整页面级组件 | `ChatPage`, `SettingsPage` |
| 布局组件 | `App` / `Layout` | 布局相关组件 | `AppHeader`, `AppContent` |

### 2. 组件粒度原则

- **单一职责**：每个组件只做一件事
- **可组合**：大组件由小组件组合而成
- **可测试**：组件行为可预测，易于单元测试
- **避免过度拆分**：不要为了拆分而拆分，保持合理粒度

## 组件 API 设计规范

### Props 设计

#### 命名规范
- 使用 camelCase
- 布尔类型用 is/has/can 开头
- 语义化命名，避免歧义

```typescript
// ✅ 推荐
const props = defineProps<{
  message: Message;
  isLoading?: boolean;
  canEdit?: boolean;
  onSend?: (content: string) => void;
}>();

// ❌ 避免
const props = defineProps<{
  msg: Message;           // 不清晰的缩写
  loadingStatus: boolean; // 冗余的后缀
  sendMsg?: Function;     // 模糊的类型
}>();
```

#### 默认值与可选性
- 有默认值的属性标记为可选
- 必要属性不标记可选
- 默认值要符合直觉

```typescript
const props = withDefaults(defineProps<{
  messages: Message[];      // 必填，无默认值
  loading?: boolean;        // 可选，有默认值
  placeholder?: string;     // 可选，有默认值
  maxLength?: number;       // 可选，有默认值
}>(), {
  loading: false,
  placeholder: '输入消息...',
  maxLength: 2000
});
```

#### Props 校验
- 复杂类型使用 TypeScript 接口定义
- 必要时使用 `validator` 进行运行时校验

```typescript
// 复杂类型定义在 types 中
interface Message {
  id: string;
  role: 'user' | 'assistant';
  content: string;
  timestamp: number;
}

// 运行时校验（必要时使用）
const props = defineProps({
  role: {
    type: String as () => 'user' | 'assistant',
    required: true,
    validator: (value: string) => ['user', 'assistant'].includes(value)
  }
});
```

### Events 设计

#### 命名规范
- 使用动词开头：send, click, change, update
- 多单词使用 kebab-case（模板中）
- 遵循 Vue 3 的 `defineEmits` 风格

```typescript
// ✅ 推荐
const emit = defineEmits<{
  (e: 'send', content: string): void;
  (e: 'retry', messageId: string): void;
  (e: 'copy', content: string): void;
  (e: 'update:modelValue', value: string): void; // v-model 支持
}>();

// 触发
emit('send', inputValue.value);
emit('update:modelValue', newValue);
```

#### v-model 支持
- 支持 v-model 的组件必须实现 `update:modelValue`
- 多值双向绑定使用 `v-model:name`

```vue
<!-- 组件内部 -->
<script setup>
const props = defineProps<{
  modelValue: string;
}>();
const emit = defineEmits<{
  (e: 'update:modelValue', value: string): void;
}>();
</script>

<!-- 使用时 -->
<ChatInput v-model="inputValue" />
```

### Slots 设计

- 必要的扩展点使用 slots
- 默认 slot 满足大多数场景
- 命名 slot 使用语义化名称

```vue
<!-- 组件定义 -->
<template>
  <div class="message">
    <slot name="avatar"> <!-- 具名 slot，有默认内容 -->
      <DefaultAvatar :role="message.role" />
    </slot>
    
    <div class="content">
      <slot name="header" />
      <slot :message="message">{{ message.content }}</slot> <!-- 作用域 slot -->
    </div>
    
    <slot name="actions" />
  </div>
</template>

<!-- 使用时 -->
<ChatMessage :message="msg">
  <template #avatar>
    <CustomAvatar />
  </template>
  
  <template #default="{ message }">
    <MarkdownRenderer :content="message.content" />
  </template>
</ChatMessage>
```

## 组件文档规范

### 组件头注释

每个组件文件顶部必须包含组件说明注释：

```vue
<!--
  @Component ChatMessage
  @Description 聊天消息组件，支持用户/助手两种角色样式
  @Usage
    <ChatMessage 
      :message="msg" 
      @copy="handleCopy"
      @retry="handleRetry"
    />
  @Props
    - message: Message - 消息对象（必填）
    - showTime?: boolean - 是否显示时间，默认 true
    - canRetry?: boolean - 是否显示重试按钮，默认 false
  @Events
    - copy: (content: string) => void - 复制消息内容
    - retry: (messageId: string) => void - 重试发送消息
  @Slots
    - avatar: 自定义头像
    - default: 自定义消息内容
    - actions: 自定义操作按钮
-->
<script setup lang="ts">
// ...
</script>
```

### 可复用逻辑抽离为 Composable

组件中可复用的逻辑必须抽离为 composable：

```typescript
// composables/useChat.ts
export function useChat() {
  const chatStore = useChatStore();
  
  const sendMessage = async (content: string) => {
    // ...
  };
  
  const loadHistory = async () => {
    // ...
  };
  
  return {
    messages: computed(() => chatStore.messages),
    isLoading: computed(() => chatStore.isLoading),
    sendMessage,
    loadHistory
  };
}
```

## 性能优化规范

### 1. 避免不必要的渲染

```vue
<!-- ✅ 使用 v-once -->
<div v-once class="chat-header">不会变的内容</div>

<!-- ✅ 长列表使用虚拟滚动 -->
<!-- 推荐：vue-virtual-scroller 或 vue-virtual-scroll-list -->
<VirtualList 
  :data="messages" 
  :item-size="80"
  key-field="id"
>
  <template #default="{ item }">
    <ChatMessage :message="item" />
  </template>
</VirtualList>
```

### 2. 计算属性缓存

```typescript
// ✅ 使用 computed 缓存计算结果
const filteredMessages = computed(() => {
  return props.messages.filter(msg => msg.content.length > 0);
});

// ❌ 不要在模板中调用复杂函数
<template>
  <!-- 每次渲染都会调用 -->
  <div v-for="msg in filterMessages(messages)" />
</template>
```

### 3. 组件懒加载

```typescript
// 路由级别的懒加载
const ChatPage = () => import('@/views/ChatPage.vue');

// 组件级别的懒加载（大组件）
const MarkdownRenderer = defineAsyncComponent(() => 
  import('@/components/chat/MarkdownRenderer.vue')
);
```

## 常见组件模式

### 1. 容器组件 vs 展示组件

**容器组件（Container）**：负责数据获取、状态管理，不包含样式
- 与 Store/Service 交互
- 处理业务逻辑

**展示组件（Presentational）**：只负责渲染，通过 props/events 通信
- 不依赖外部状态
- 可复用性高

### 2. Renderless 组件

只提供逻辑，不渲染任何 DOM，通过 slot 提供 API：

```vue
<script setup>
const { isHovered, bind } = useHover();
defineExpose({ isHovered });
</script>

<template>
  <slot :is-hovered="isHovered" :bind="bind" />
</template>
```
