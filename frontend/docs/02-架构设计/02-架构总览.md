# 架构设计文档

## 概述

本文档定义 OmniBot 前端架构设计，包括目录结构、模块划分、数据流设计等。

---

## 设计原则

### 1. 分层架构
- **视图层（View）**：页面组件，只负责渲染和用户交互
- **状态层（Store）**：Pinia 管理全局状态
- **服务层（Service）**：API 封装、业务逻辑处理
- **工具层（Utils）**：通用工具函数

### 2. 单一职责
- 每个组件/模块只负责一件事
- 组件只处理 UI 逻辑，业务逻辑抽离到 service/composable

### 3. 类型安全
- 全程 TypeScript，禁止 `any`
- API 响应类型定义完善
- Store 状态类型完整

## 数据流设计

### 聊天消息数据流

```
用户输入 → View (Chat.vue) 
           → Composable (useChat) 
             → Store (chatStore.addMessage) 
               → Service (chatService.sendMessage) 
                 → API 请求 
                   → Store 更新状态 
                     → View 响应式渲染
```

### 数据流向原则

1. **单向数据流**：数据只能从 Store 流向 View，View 通过 actions 修改 Store
2. **API 调用统一入口**：所有 API 调用通过 Service 层，不直接在组件中调用 axios
3. **状态持久化**：必要状态通过 localStorage 持久化（sessionId、设置等）

## 核心模块设计

### 1. 聊天模块 (Chat)

#### 职责划分
- **Chat.vue**：页面布局、组件组合
- **chatStore**：消息列表、加载状态、会话信息
- **useChat**：发送消息、加载历史、消息处理逻辑
- **chatService**：API 调用封装
- **组件**：MessageList、MessageItem、MessageInput、QuickActions

#### 状态定义
```typescript
interface ChatState {
  messages: Message[];        // 消息列表
  isLoading: boolean;         // 发送中状态
  sessionId: string;          // 会话 ID
  hasMore: boolean;           // 是否有更多历史
}
```

### 2. 设置模块 (Settings)

#### 职责划分
- SettingsPanel.vue：设置面板组件
- settingsStore：LLM 配置、主题设置等
- settingsService：保存/读取配置 API

### 3. 会话模块 (Session)

#### 职责划分
- useSession：会话管理 composable
- 本地存储：sessionId 持久化
- 自动生成：新用户自动生成 UUID

## 状态管理设计

### Store 划分原则

1. **按业务领域划分**，不是按技术维度
2. **每个 Store 职责单一**
3. **Store 之间可以互相调用**

### Store 类型

| Store | 职责 | 持久化 |
|-------|------|--------|
| chatStore | 消息列表、发送状态、会话 ID | ✅ (消息列表) |
| userStore | 用户信息、配置 | ✅ |
| settingsStore | 主题、LLM 配置、显示设置 | ✅ |
| uiStore | 全局 UI 状态（侧边栏、弹窗） | ❌ |

## 接口设计规范

### API 响应统一格式
```typescript
interface ApiResponse<T = any> {
  success: boolean;
  data: T;
  error?: {
    code: string;
    message: string;
  };
}
```

### 请求拦截器职责
1. 统一添加请求头（Content-Type、Authorization）
2. 请求日志（开发环境）
3. 请求取消处理

### 响应拦截器职责
1. 统一错误处理（401、403、500 等）
2. 响应数据转换
3. 响应日志（开发环境）
4. 超时处理
